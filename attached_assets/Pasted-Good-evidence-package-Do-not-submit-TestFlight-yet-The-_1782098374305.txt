The remaining decision is anonymous access.

Website Ora supports anonymous usage through /api/public-ai/session with limited quota, and your runtime proof confirms the endpoint works anonymously. Therefore, mobile requiring sign-in is a real parity gap.

Decision: implement Option B before TestFlight.

Ora Mobile should support anonymous chat mode like the website.

Required anonymous mobile behavior:

1. Signed-out users must be able to open Ora chat without being forced to sign in.
   - Remove the hard redirect that blocks app/(home).
   - Allow anonymous access to the main Ora chat screen.

2. Anonymous mode should use the same backend behavior as website:
   - POST /api/public-ai/session without Clerk token
   - anonymous message quota from backend
   - same usage/reset fields from session response
   - no mobile-side quota logic

3. Anonymous users should be allowed:
   - main Ora chat
   - Instant mode if website allows it
   - temporary chat if compatible
   - diagnostics
   - light/dark mode
   - language selector
   - basic sources/media rendering from chat replies

4. Anonymous users should be gated or prompted to sign in for account-bound features:
   - Memory Center
   - saved memories
   - projects
   - persistent conversation history
   - Library/assets
   - ORAX if auth-bound
   - billing/subscription/settings account features
   - file storage or generated asset persistence if auth-bound
   - Deep Thinking if not available to anonymous/free tier

5. UI requirements:
   - Show anonymous/signed-out state clearly.
   - Plan badge should either be hidden or show the same website anonymous/free treatment.
   - When anonymous users tap a gated feature, show a native sign-in prompt.
   - Do not silently fail or redirect without explanation.

6. Persistence requirements:
   - Anonymous chats should behave like website anonymous chats.
   - Do not write memory.
   - Do not save persistent project/history unless backend supports anonymous persistence.
   - Respect backend limits exactly.

7. Diagnostics:
   - Diagnostics must work signed out.
   - It should prove anonymous session + chat path:
     - transport
     - /api/public-ai/session
     - /api/public-ai/chat temporary “hi”
     - stream if enabled

8. Ora isolation still required:
   - no Builder UI
   - no Builder CTA
   - no Builder handoff
   - no /api/builder/*
   - no /public-ai/handoff/create
   - no mobile-side model/provider routing

- Ora isolation / no Builder reference scan
- runtime diagnostics signed out
- runtime diagnostics signed in
- main chat “hi” signed out
