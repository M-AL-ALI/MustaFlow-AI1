Users are reporting Ora is slow on BOTH:
1. Talk to Ora voice
2. Normal Ora AI chat text responses on website + mobile

Please do a full latency audit, not only realtime voice.

For normal Ora chat, measure these buckets separately:
- client send click/tap → API request received
- API request received → auth/session resolved
- auth/session resolved → user tier resolved
- tier resolved → memory/context loaded
- memory/context loaded → routing/model selected
- model selected → provider request started
- provider request started → first token received
- first token received → first token streamed to client
- first token streamed → response complete
- response complete → memory save / transcript save / post-processing complete

For Talk to Ora, keep existing buckets:
- speech_stopped → transcript_completed
- transcript_completed → focus decision
- focus decision → response_create_sent
- response_create_sent → response.created
- response.created → output_audio_started
- output_audio_started → audible playback
- response.done

Test cases:
Website:
- short simple prompt
- long reasoning prompt
- Arabic prompt
- prompt with memory context
- prompt that should NOT need web search
- prompt that DOES need web search
- paid Core account
- free account

Mobile:
- same prompts
- fresh app launch
- after app background/foreground
- signed-in paid account
- weak network if possible

Things to check:
- Is Ora waiting for memory/context before streaming?
- Is memory extraction blocking the response instead of running after?
- Is routing/fallback adding delay?
- Are provider calls timing out or retrying silently?
- Is web search triggered too often?
- Is the client buffering streamed tokens before showing them?
- Is mobile using the same streaming path as website?
- Is auth/account/session sync blocking chat start?
- Is the first visible token delayed even if the model already started?
- Are responses too long for simple prompts?
- Is the model choice too slow for simple chat?
- Are logs showing slow DB queries or cold starts?

Required diagnostics:
Add privacy-safe timing logs for Ora text chat, similar to Talk to Ora diagnostics:
- no raw prompt text
- no raw transcript
- no private memory text
- only timings, tier, route, model family, provider, fallback used, search used, memory count, token counts, error/retry flags

Acceptance goals:
- Simple text prompt should start streaming quickly.
- First visible token should be close to ChatGPT feel.
- Mobile and website should use equivalent chat pipeline.
- Memory/search should not block unnecessarily.
- Search should only run when needed.
- Post-response memory saving should happen after streaming, not before first answer.
- If provider is slow, fallback should be visible in diagnostics.
- If mobile UI is buffering, fix mobile streaming/rendering.

Do not guess. First identify the slow bucket, then tune the exact layer.
