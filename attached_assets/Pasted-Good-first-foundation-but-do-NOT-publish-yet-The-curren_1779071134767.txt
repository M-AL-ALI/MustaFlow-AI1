--------------------------------------------------
REQUIRED BUILDER PIPELINE
--------------------------------------------------

Create this AI builder pipeline:

User prompt
→ App Blueprint
→ File Generation
→ Save Project Files
→ Preview Build
→ Test/Validation
→ Version Save
→ Final Report

1. App Blueprint

Create a structured blueprint object from the user prompt.

Blueprint must include:
- projectName
- projectType
- targetPlatforms
- pages/screens
- navigation
- components
- data needed
- backend needs
- integrations needed
- API keys needed
- styling/theme
- user roles if any
- testing checklist

Example blueprint:

{
  "projectName": "Towing Service Website",
  "projectType": "website",
  "targetPlatforms": ["web"],
  "pages": [
    {"name": "Home", "route": "/"},
    {"name": "Services", "route": "/services"},
    {"name": "Booking", "route": "/booking"},
    {"name": "Contact", "route": "/contact"}
  ],
  "components": ["Hero", "ServiceCards", "BookingForm", "Navbar", "Footer"],
  "integrationsNeeded": ["Email provider optional", "Maps optional"],
  "requiredKeys": [],
  "theme": "modern dark professional"
}

2. File Generation

Use the blueprint to generate real files.

For Phase 2, generate files like:
- src/App.tsx
- src/pages/Home.tsx
- src/pages/Services.tsx
- src/pages/Booking.tsx
- src/pages/Contact.tsx
- src/components/Navbar.tsx
- src/components/Footer.tsx
- src/components/Hero.tsx
- src/components/ServiceCards.tsx
- src/styles/theme.css or Tailwind classes
- package/project metadata if needed

3. Save Project Files

Generated files must appear in Tools & Files.

The file tree must show the generated files.

Opening a file should show its content.

4. Live Preview

The Preview tab must show the generated app result, not just a static placeholder.

Create a preview route like:

GET /preview/:projectId

or an iframe/rendering system that displays the generated web app.

For safety in Phase 2:
- Do not execute dangerous arbitrary code.
- Use a controlled React preview renderer or safe generated template system.
- Keep preview sandboxed.

5. Change Requests

When user says:

“Make the button blue”
“Add a pricing section”
“Add a booking form”
“Make it look more professional”
“Add a dashboard page”

The AI must:
- Identify affected files
- Create a mini plan
- Apply changes to the correct files
- Save a new version
- Refresh preview
- Write a report

6. Version History

Every generation or change must create:
- versionId
- taskId
- timestamp
- user prompt
- files changed
- before/after summary
- rollback point

7. Rollback

The rollback button can still be simple, but it must restore the previous saved file contents for that project.

8. Reports

Every builder task must end with a report:

- What user requested
- Blueprint generated
- Files created
- Files changed
- Preview updated: yes/no
- Tests/validation run
- Warnings
- Next recommendation

--------------------------------------------------
PLAN MODE BEHAVIOR
--------------------------------------------------

If Plan Mode is ON:
- Do not generate files immediately.
- Create the blueprint and plan only.
- Ask user:
  “Do you want me to build this in Main Agent or Background Agent?”

If Plan Mode is OFF:
- Generate the project directly, but still create a version and report.

--------------------------------------------------
MAIN AGENT VS BACKGROUND AGENT
--------------------------------------------------

Main Agent:
- Build immediately
- Show progress
- Update preview

Background Agent:
- Create background task
- Run generation/change task
- Return final report
- Show completed task in background task list

Background task must not just auto-complete fake work. It must run the same generation/change pipeline.

--------------------------------------------------
INTEGRATION RECOMMENDATION ENGINE
--------------------------------------------------

The AI must detect needed integrations.

Example:
If user asks for payments:
- recommend Stripe
- ask for test keys first
- explain production keys later

If user asks for maps:
- recommend Google Maps / Apple Maps
- explain required keys

If user asks for login:
- recommend Clerk/Auth0/Supabase Auth
- explain needed publishable and secret keys

If user asks for SMS:
- recommend Twilio
- explain needed SID/token/phone number

For now, do not require all integrations to be fully connected, but the AI must clearly list:
- what integration is needed
- what key/account is needed
- where the user should add it in Secrets
- whether it is testing or production
