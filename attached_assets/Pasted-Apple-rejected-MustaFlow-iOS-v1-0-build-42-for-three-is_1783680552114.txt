Apple rejected MustaFlow iOS v1.0 build 42 for three issues. Please fix only the App Store rejection items. Do not touch Ora chat, Talk to Ora, billing, search, images, files, history, ORAX, or website behavior unless directly required for Apple login.

Issue 1 — Guideline 2.3.6 Age Rating
This is App Store Connect metadata, not code.
In App Store Connect → App Information → Age Rating, update the questionnaire so the app does NOT claim Parental Controls / In-App Controls unless those features actually exist. The correct answer should likely be “None” for Parental Controls.
No build required for this item.

Issue 2 — Guideline 2.1 Demo Account
This is App Store Connect review access, not code unless the production account cannot log in.
Create/verify a production review account that works in the TestFlight/App Store build:
- Email/password must work directly.
- No email verification code step.
- No 2FA.
- No inbox access required by reviewer.
- Account must have enough access to review the app.
Update App Review Information with the exact email/password and notes:
“Use the email and password provided. No email verification code is required.”

Issue 3 — Guideline 4.8 Login Services
Because the app offers Google login, Apple requires Sign in with Apple or an equivalent privacy-preserving login option. Implement native Sign in with Apple in the mobile app.

Required implementation:
1. Enable Apple provider in Replit Auth / Clerk production configuration.
2. Enable “Sign in with Apple” capability for Apple App ID: com.mustaflow.app.
3. Ensure the EAS/Apple provisioning profile includes the Sign in with Apple entitlement.
4. Add expo-apple-authentication if not already installed.
5. Update Expo config:
   - app.json / app.config should include iOS usesAppleSignIn: true.
   - Add the Apple authentication plugin if required by Expo.
6. Add “Continue with Apple” button everywhere “Continue with Google” appears:
   - sign-in screen
   - sign-up screen
   - any auth wall / sign-in prompt if Google appears there
7. Button must have equal prominence to Google and follow Apple styling requirements.
8. Use native Apple auth flow, not a web-only workaround.
9. Wire Apple auth into Clerk SSO so the result signs into the same production user system.
10. Handle user cancel silently.
11. Show a normal error toast only for real Apple/Clerk failures.
12. Keep Google and email/password login unchanged.

Verification required before new build:
- Production Clerk/Replit Auth has Apple enabled.
- Apple Developer App ID has Sign in with Apple capability.
- iOS entitlement/provisioning profile includes Sign in with Apple.
- On physical iPhone/TestFlight:
  - Email/password review account signs in.
  - Google sign-in still works.
  - Apple sign-in works.
  - New Apple user can enter Ora.
  - Existing user can still enter Ora.
  - Sign out/sign in again works.
  - No auth screen layout issues.
- Run mobile typecheck and relevant auth/source tests.
- Confirm no unrelated files changed.

After verification:
- Cut new TestFlight build with build number higher than 42.
- Submit the new build.
- In App Review notes, include:
  - demo email
  - demo password
  - “No email verification code is required”
  - “Sign in with Apple is available on the sign-in and sign-up screens”
