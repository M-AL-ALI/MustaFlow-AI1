Goal

Phase 2I should make Orax perform the first real agentic step inside a project thread.

Right now run_project_thread mainly verifies context. That is useful, but it does not yet act like a coding agent. The next step is to make Orax Desktop inspect the project folder and send back meaningful inline thread output.

In simple words:

User sends a message in an Orax Project thread.
Backend queues run_project_thread.
Desktop verifies project/source.
Desktop inspects the local project safely.
Desktop returns project context summary and suggested next step.
Backend writes the result inline into the Orax thread.

Do not touch Ora, public-ai chat, AI Builder, credits, or normal project chat.

Core Behavior

When desktop receives run_project_thread:

1. Validate payload:
- projectId
- threadId
- executionSourceId
- sourceLocalPath
- userMessage

2. Verify local binding:
- sourceLocalPath exists.
- `.orax/project.json` exists or is created safely.
- If `.orax/project.json` has a different projectId, fail.
- If executionSourceId mismatches, fail or mark as mismatch.
- Do not fall back to process.cwd().

3. Inspect project safely:
- Read lightweight filesystem structure only.
- Do not read secrets.
- Do not read huge files.
- Do not read node_modules, .git internals, dist/build/out/cache folders.
- Detect:
  - package manager
  - framework
  - key config files
  - package.json scripts
  - git branch if available
  - whether repository exists
  - common app folders
  - test/lint/build scripts
  - existing `.orax/project.json`

4. Return an inline result:
- Summary of what desktop found.
- Suggested next step.
- If enough context exists, propose a plan.
- If project lacks setup, say what is missing.
- Keep it short and Codex-like, not a dashboard dump.

Example result:

“Orax connected to this project and inspected the local workspace.

Detected:
- pnpm TypeScript monorepo
- Vite/React web app
- Expo mobile app
- API server package
- Git repository on branch main

Useful scripts:
- pnpm run typecheck:libs
- pnpm --filter @workspace/mustaflow run typecheck
- pnpm --filter @workspace/api-server run typecheck

Next: I can inspect the files related to your request and prepare the first change.”

5. Backend should write this result into the project thread:
- role: assistant or system depending existing convention
- eventType: project_context_inspected or similar
- payload includes structured metadata
- visible thread content should be human-friendly

Important

Everything must remain inline in the project thread.
No new dashboard panel.
No workflow log wall.
No raw JSON dump in the UI.
No approval IDs or artifact IDs shown to the user.

Desktop Implementation

Add a safe project inspector in Orax Desktop.

Suggested file:
artifacts/orax-desktop/src/main/project-inspector.ts

It should export something like:

inspectLocalProject(localPath: string): Promise<ProjectInspectionResult>

ProjectInspectionResult:
- rootName
- localPath
- hasGit
- gitBranch
- packageManager
- frameworkHints[]
- scripts[]
- keyFiles[]
- topLevelEntries[]
- ignoredEntries[]
- warnings[]
- summaryText

Safety rules:
- Never traverse node_modules.
- Never traverse .git.
- Never traverse dist, build, out, coverage, .next, .expo, .turbo, .cache.
- Max depth 3.
- Max files inspected 200.
- Max package.json size 200KB.
- Do not read .env, *.pem, *.key, id_rsa, secrets.*.
- Only read safe metadata files:
  - package.json
  - pnpm-workspace.yaml
  - tsconfig.json
  - vite.config.*
  - next.config.*
  - expo/app.json
  - app.json
  - README.md first 8KB only
  - turbo.json
  - nx.json
  - workspace config files

Use Node fs APIs, not shell commands, for inspection.
