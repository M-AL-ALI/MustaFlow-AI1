I need to clarify something important.

I should not have to manually click “Ask AI to fix this” for every issue that Agent Zero already detected.

If Agent Zero sees the issue during the build, through checks, logs, preview status, TypeScript, install, server-start, or healthz, then Agent Zero should automatically attempt the correct repair flow.

The “Ask AI to fix this” button should be a manual override, not the primary repair mechanism.

My expectation:

Agent Zero should work like this:

1. User asks to build an app.
2. Agent Zero plans/builds.
3. Agent Zero writes files.
4. Agent Zero runs checks.
5. If install fails, Agent Zero fixes install.
6. If TypeScript fails, Agent Zero fixes TypeScript.
7. If build fails, Agent Zero fixes build.
8. If server-start fails, Agent Zero fixes server startup.
9. If preview is unreachable, Agent Zero diagnoses preview/runtime/proxy.
10. Agent Zero reruns checks.
11. Agent Zero updates preview.
12. Only then does it report final status.

The user should not have to babysit the agent.

Required change:
Add an automatic repair controller/supervisor after every check phase.

When a validation issue is detected, the system should automatically classify it and trigger the right repair path.

Examples:

* TypeScript failed → automatically run TypeScript repair.
* Missing dependency → automatically update package.json and install.
* Missing local import/file → automatically create missing file or fix import.
* Build failed → automatically inspect build output and patch.
* Server-start failed → automatically inspect logs, scripts, port, entrypoint, healthz.
* Preview unreachable → automatically check server, proxy, DNS, container status, and healthz.
* Install failed → automatically inspect npm/yarn logs and categorize OOM, lock, network, missing package, peer conflict, or file error.

The “Ask AI to fix this” button should remain, but only for:

* user wants to manually retry
* user wants to force a specific repair
* the task ended blocked
* the user wants to override or prioritize one issue
* the system needs approval before running a risky command

It should not be required for normal repair.

Also:
If multiple issues exist, Agent Zero should prioritize them automatically:

Priority order:

1. dependency install
2. missing files/imports
3. TypeScript/build
4. server-start/healthz
5. preview reachability
6. UI interaction
7. lint/refactor/cleanup

Do not make the user choose Fix TypeScript, Fix Build, Fix Server, Fix Preview manually when the system already knows what failed.

The correct final behavior should be:

“Agent Zero detected 4 validation issues. I will fix them in order: dependencies → TypeScript/build → server-start → preview. I will stop if a blocker requires your approval.”

Acceptance criteria:

1. A build with detected validation issues automatically creates a repair attempt.
2. The repair attempt uses issue-specific prompts without user clicking Ask AI.
3. The system does not keep writing features while foundation checks fail.
4. If auto-repair succeeds, preview refreshes.
5. If auto-repair fails, final status is honest and shows the exact blocker.
6. “Ask AI to fix this” remains as a manual fallback, not the main path.
7. The user can steer the repair, but does not have to babysit it.

This is very important.

If the AI can see the error, the AI should try to fix the error automatically.
That is the point of Agent Zero.
