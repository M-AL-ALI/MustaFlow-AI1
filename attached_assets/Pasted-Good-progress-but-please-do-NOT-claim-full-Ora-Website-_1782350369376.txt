2. Generated-document export parity is still NOT complete
Please be precise in wording.

Mobile now supports:
- Markdown export
- JSON export
- CSV/action-plan export
- real PDF export via expo-print
- backend-generated files saved/shared natively
- generated/edited images saved natively

But mobile still does NOT fully match website fidelity for:
- Word export
- Excel export
- Slides export

Website:
- Word = real .docx
- Excel = real .xlsx
- Slides = real .pptx

Mobile currently:
- Word = .rtf stand-in
- Excel = .csv stand-in
- Slides = .html stand-in

So please do not say “all export formats match the website.”
Correct wording:
“All export actions exist on mobile, PDF is now real, backend-generated binary files are full parity, but client-side Word/Excel/Slides binary fidelity remains deferred.”

If you want to close this gap later:
- Word: likely use `docx` with base64 output.
- Excel: evaluate RN-safe SheetJS or another lightweight approach.
- Slides: `pptxgenjs` may be risky in React Native because of DOM/Blob assumptions.
Do not rush these into the current build unless tested carefully on Hermes/iOS.

3. Talk-to-Ora lifecycle improvement is good, but needs real iPhone QA
The code now distinguishes:
- `inactive`: abort in-flight TTS synthesis, but do not fully tear down Talk mode.
- `background`: fully tear down the voice loop: stop recorder, remove TTS player, reset audio mode, exit Talk mode.

This is a reasonable approach, but it must be tested on a real iPhone.

Please test:
- Start Talk mode, then pull Control Center.
- Start Talk mode, then open app switcher.
- Start Talk mode, then trigger Face ID / system prompt if possible.
- Start Talk mode, then receive a call/banner interruption.
- Start Talk mode while recording, then lock the phone.
- Start Talk mode while TTS is generating, then background the app.
- Start Talk mode while TTS is playing, then background the app.
- Return to the app after each case.

Expected:
- No stuck recording.
- No TTS starts after the app was backgrounded.
- No late audio playback after leaving the app.
- No repeated auto-listen loop while inactive/backgrounded.
- On quick inactive interruptions, Talk mode can continue cleanly when app becomes active again.
- On full background, Talk mode exits cleanly.
