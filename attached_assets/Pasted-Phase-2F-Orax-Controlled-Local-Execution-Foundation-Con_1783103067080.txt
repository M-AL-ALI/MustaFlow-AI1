Phase 2F — Orax Controlled Local Execution Foundation

Context:
Phase 2E is complete and verified.

Current Orax state:
- Orax Desktop exists and builds.
- Desktop registers as an Orax host.
- Website/mobile can detect online/offline desktop hosts.
- Website/mobile can pair/manage desktop devices.
- Backend can queue safe desktop actions.
- Desktop polls backend for actions.

- Ora/public-ai/AI Builder/credits/project chat are untouched.

Goal of Phase 2F:
Add the first controlled local execution capability, but safely.

Orax should be able to request approval to run a simple local command on the desktop, the user approves it, the desktop executes it, and the result appears inline.

This phase is NOT full autonomous coding yet.
This phase is the permission-gated execution foundation.

Do not implement unrestricted PowerShell.
Do not implement file editing.
Do not implement git commit/push/PR yet.
Do not implement package install yet.
Do not bypass approvals.

Do not touch:
- Ora
- public-ai
- AI Builder
- credits
- project chat
- existing Ora routes

Part B — Approval model

Use `orax_pending_approvals`.

When web/mobile asks Orax to run a command:
1. Backend creates a pending approval.
2. Backend creates an action with status `queued_approval` or similar.
3. UI shows approval inline:
   - Command to run
   - Working directory
   - Risk level
   - Reason
   - Approve button
   - Deny button
4. Only after approval does the action become queued for desktop.

Approval status:
- pending
- approved
- denied
- expired

Add expiration:
- Default approval expires after 10 minutes.

Part C — Backend endpoints

Add endpoints:

POST /api/orax/hosts/:hostId/command-approvals

Payload:
{
  threadId?: string;
  projectId?: string;
  command: string;
  cwd?: string;
  reason: string;
}

Behavior:
- Validate user owns host.
- Validate host not revoked.
- Validate command is safe or classify as blocked.
- Create orax_pending_approvals row.
- Return approval.
- Append thread message if threadId exists:
  “Approval requested to run: <command>”

POST /api/orax/approvals/:approvalId/resolve

Payload:
{
  decision: "approved" | "denied"
}

Behavior:
- Validate approval belongs to user.
- If denied:
  - mark approval denied
  - append thread message
  - do not queue action
- If approved:
  - mark approval approved
  - create `run_safe_command` action for desktop
  - append thread message
  - return action

GET /api/orax/threads/:threadId/approvals
If already exists, reuse existing approval loading route. If not, add it for desktop approvals.

Important:
Do not mix this with old Orax GitHub/file approval system unless it is already clearly shared. If reusing helpers, make sure route names and table ownership stay Orax Desktop-specific.

Part D — Command safety classifier

Add a backend command safety classifier.

Suggested file:
artifacts/api-server/src/lib/orax-command-safety.ts

Function:
classifyOraxCommand(command: string): {
  allowed: boolean;
  risk: "low" | "medium" | "high" | "blocked";
  reason: string;
  normalizedCommand: string;
}

Rules:
- Trim command.
- Reject empty command.
- Reject command chains:
  - &&
  - ||
  - ;
  - |
  - >
  - >>
  - <
  - ``
  - $()
- Reject destructive commands.
- Reject secret-reading patterns.
- Reject network commands.
- Reject install/push/commit commands in Phase 2F.
- Allow only exact allowlist commands or narrow safe patterns.

Safe examples:
- node --version
- npm --version
- pnpm --version
- git --version
- pwd
- dir /b
- Get-ChildItem -Name
- echo hello

Blocked examples:
- del package.json
- Remove-Item -Recurse .
- git push
- pnpm add lodash
- npm install
- cat .env
- Get-Content .env
- curl https://example.com
- powershell -EncodedCommand xxx
- dir && del file

Add unit or wiring tests for all examples.

Part E — Desktop executor

Add desktop executor files:

artifacts/orax-desktop/src/main/command-executor.ts
artifacts/orax-desktop/src/main/permission-gate.ts

Command executor:
- Executes only actions of type `run_safe_command`.
- Re-validates command locally before execution.
- Uses child_process.spawn, not exec.
- No shell interpolation.
- Timeout default: 30 seconds.
- Max output capture: 20 KB stdout, 20 KB stderr.
- Kill process on timeout.
- Return:
  - exitCode
  - stdout
  - stderr
  - durationMs
  - timedOut

Important:
Use safe spawn argument parsing.
Do not pass untrusted command to shell: true.
Do not use exec.

For Windows:
- Support safe PowerShell command:
  Get-ChildItem -Name
- Prefer spawning:
  powershell.exe -NoProfile -Command Get-ChildItem -Name
only for allowlisted PowerShell commands.

For simple commands:
- node --version → spawn("node", ["--version"])
- pnpm --version → spawn("pnpm", ["--version"])
- git --version → spawn("git", ["--version"])

Part J — Security

Required protections:
- User must own host.
- Host must not be revoked.
- Action must be approved before desktop can receive it.
- Desktop must re-check safety locally.
- No environment variable dumps.
- No secrets in stdout/stderr if simple redaction helper exists.
- Redact common token patterns from output:
  - sk-...
  - ghp_...
  - github_pat_...
  - Bearer ...
  - .env values if detected
- Unknown action types rejected.
- Repeated idempotency keys must not double-run commands.
- Command output stored only in Orax Desktop action result / Orax thread message, not Ora.
