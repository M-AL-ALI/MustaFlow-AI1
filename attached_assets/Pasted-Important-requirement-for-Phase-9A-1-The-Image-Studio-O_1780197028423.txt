Important requirement for Phase 9A-1:

The Image Studio / Ora image generation feature must not interfere with AI Builder Mode, Developer Mode, Plan Mode, or existing project-building workflows.

Please add this as a hard boundary in the final Phase 9A-1 implementation plan.

Non-interference requirements

Phase 9A-1 must be isolated from:

* AI Builder Mode
* Developer Mode
* Plan Mode
* Project workspace build/refine pipelines
* Builder chat logic unless explicitly wiring a safe image-generation command
* project file writing
* deployment flows
* background jobs used for app generation
* Knowledge Vault / Phase 8B
* RAG / AI memory
* Web Search
* Advanced Charts

Required architecture boundary

Image generation should use its own isolated system:

* separate API routes under /api/images
* separate image provider service
* separate image storage helper
* separate generated image metadata table
* separate credit/rate-limit logic for images
* separate UI page /image-studio
* optional safe authenticated chat integration only through an explicit image intent

Do not modify Builder pipelines directly.

Do not modify Developer Mode tools directly.

Do not modify Plan Mode.

Do not change project files automatically.

Do not insert generated images into apps automatically in Phase 9A-1.

AI Builder / Developer Mode protection

Before writing code, please inspect the actual Builder and Developer Mode files and document what is untouched.

Confirm these remain unchanged unless there is a clearly necessary import-free route registration:

* builder pipeline files
* project workspace page
* runtime/developer tools
* terminal/files routes
* plan mode routes
* deployment routes
* project file mutation routes
* app generation jobs
* project preview logic

If any file from Builder/Developer/Plan Mode must be touched, stop and explain why before changing it.

Authenticated chat integration rule

If Phase 9A-1 adds image generation inside authenticated chat, it must be routed as an explicit image-generation intent only.

Normal builder prompts like:

* “build my app”
* “fix this page”
* “change my database”
* “deploy my project”
* “debug this error”

must continue to go to the existing Builder/Developer/Plan flows.

Image generation intent must only trigger for clear image requests such as:

* create image
* generate picture
* make logo
* create app icon
* generate banner
* create hero image
* make report cover
* create social media graphic
* design illustration

Do not hijack normal Builder requests.

Public Ora rule

Public landing-page Ora must not call image generation APIs.

If an unauthenticated visitor asks for image generation, public Ora should show a sign-in / open Image Studio CTA only.

Project integration boundary

For Phase 9A-1:

* “Use in Project” can exist only as disabled placeholder:
    Use in Project — Coming in Phase 9A-3
* it must not call an API
* it must not write project files
* it must not replace logos/icons
* it must not modify app screens
* it must not trigger Builder pipelines

Actual project insertion belongs to Phase 9A-3 or later.
