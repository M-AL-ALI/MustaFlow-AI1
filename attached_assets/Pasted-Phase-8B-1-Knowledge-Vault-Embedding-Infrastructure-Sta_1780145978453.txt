Database Design

Create a new table:

vault_embeddings {
  id: string;
  entryId: number;
  userId: string;
  chunkIndex: number;
  chunkText: string;
  chunkHash: string;
  embedding: vector;
  embeddingModel: string;
  sourceVersion: number;
  createdAt: Date;
  updatedAt: Date;
}

If pgvector is not available yet, stop and report before implementing an alternative.

Do not fake embeddings.

Do not store embeddings as plain JSON unless explicitly approved.

Preferred:

* PostgreSQL pgvector
* vector dimension based on selected embedding model

⸻

Embedding Model

Use a modern OpenAI embedding model if already available in the project’s provider layer.

Recommended:

* text-embedding-3-small

Reason:

* lower cost
* good semantic retrieval quality
* suitable for vault search foundation

If model/provider wiring is unclear, stop and ask before proceeding.

⸻

Chunking Rules

Each Knowledge Vault entry should be converted into chunks using:

* title
* category
* department
* tags
* summary
* content

Chunking requirements:

* chunk size target: 800–1200 tokens or equivalent character range
* overlap: small overlap only if needed
* preserve source metadata
* include entry id and version
* do not include secrets or internal refs
* run sanitizer before embedding

Each chunk must store:

* entryId
* userId
* chunkIndex
* chunkText
* chunkHash
* sourceVersion

⸻

Reindex Logic

Create a service such as:

reindexVaultEntry(entryId, userId)
reindexAllVaultEntries(userId)
deleteEmbeddingsForEntry(entryId, userId)
getEmbeddingStatus(entryId, userId)

Behavior:

1. Load vault entry with ownership check.
2. Sanitize entry.
3. Chunk entry.
4. Hash each chunk.
5. Skip chunks with unchanged hash.
6. Generate embeddings for changed chunks.
7. Store embeddings.
8. Delete stale chunks that no longer exist.
9. Return status.

⸻

Manual Only

Phase 8B-1 must be manual only.

Allowed:

* User clicks “Rebuild Embeddings”
* User clicks “Reindex Vault”
* Admin/manual action triggers reindex

Not allowed:

* automatic background reindexing
* automatic embedding on every save
* automatic AI learning
* automatic prompt usage

We will add controlled automation later if needed.

⸻

API Routes

Create authenticated routes only.

Suggested routes:

POST /api/vault/:id/reindex
POST /api/vault/reindex
GET  /api/vault/:id/embedding-status

All routes must:

* require authentication
* enforce ownership
* never expose another user’s embeddings
* never expose raw embedding vectors to the frontend unless explicitly needed
* return only status and counts

Example response:

{
  "entryId": 123,
  "status": "indexed",
  "chunkCount": 4,
  "embeddingModel": "text-embedding-3-small",
  "sourceVersion": 2,
  "updatedAt": "..."
}

Security Requirements

Before embedding, reuse the vault sanitizer.

Never embed:

* API keys
* secrets
* tokens
* passwords
* connection strings
* session identifiers
* handoff tokens
* Builder secrets
* deployment secrets
* private credentials
* internal infrastructure IDs
* base64 payloads
* fileRef
* imageRef
* datasetRef

If sensitive content is detected:

* block embedding
* show safe error message
* do not send content to embedding model

⸻

Privacy Requirements

Embeddings are user-scoped.

Rules:

* user can only index their own entries
* user can only see status for their own entries
* user cannot access another user’s embedding rows
* raw embedding vectors should not be returned in normal API responses
* no embedding content should be logged
* no chunk text should be logged
* no raw vault content should be logged

Safe logs only:

* entryId
* userId hash if needed
* chunk count
* model name
* duration
* success/failure category
