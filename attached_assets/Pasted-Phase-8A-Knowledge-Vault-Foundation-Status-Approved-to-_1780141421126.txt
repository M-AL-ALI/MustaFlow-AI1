Phase 8A — Knowledge Vault Foundation

Status: Approved to Begin

Goal

Build the foundation for the MustaFlow AI Knowledge Vault.

The purpose is to let users save, organize, search, review, edit, version, and archive approved knowledge from reports, investigations, corrective actions, lessons learned, SOPs, standards, and improvement projects.

This phase is foundation only.

Do not implement autonomous AI learning yet.

Do not implement automatic memory injection yet.

Do not implement RAG, vector search, semantic search, or embeddings yet.

Do not allow Ora to permanently learn anything unless the user explicitly approves saving it.

⸻

Core Principle

Knowledge Vault is not uncontrolled memory.

Knowledge Vault is a structured, permission-controlled organizational intelligence repository.

Every saved item must be:

* User-approved
* Searchable
* Categorized
* Tagged
* Versioned
* Timestamped
* Attributed to a source
* Editable
* Archivable
* Permission-controlled
* Sanitized before saving

Nothing should be automatically saved without user action.

Required Features

1. Save to Knowledge Vault

Add a “Save to Knowledge Vault” action in the appropriate Ora/report surfaces.

User should be able to save:

* Dataset analysis
* Generated reports
* Root cause reports
* Corrective action reports
* Executive reports
* Operations reports
* Strategic reports
* Lessons learned

Save flow:

1. User clicks “Save to Knowledge Vault”
2. A review modal opens
3. User reviews title, category, department, tags, summary, and content
4. User confirms save
5. Entry is saved
6. Entry appears in the Knowledge Vault tab

No automatic saving.

⸻

⸻

5. Versioning

Every edit should create a new version.

Rules:

* Never destructively overwrite prior content
* Version starts at 1
* Each update increments version by 1
* Previous versions remain viewable
* Version history shows:
    * version number
    * edited by
    * edited date
    * summary of changes if available

Suggested model:

KnowledgeVaultVersion {
  id: string;
  entryId: string;
  version: number;
  title: string;
  summary: string;
  content: string;
  tags: string[];
  department?: string;
  editedBy: string;
  editedAt: Date;
}

⸻

6. Security and Sanitization

Before saving any entry, sanitize the content.

Must never store:

* API keys
* Secrets
* Tokens
* Passwords
* Connection strings
* Session identifiers
* Handoff tokens
* Builder secrets
* Deployment secrets
* Private credentials
* Internal infrastructure IDs
* Base64 payloads
* File references
* Image references
* Dataset references

Reuse the existing sanitizer where possible.

If sensitive content is detected, either:

* remove/redact it automatically, or
* block the save and tell the user what needs to be removed

⸻

7. Permissions

Knowledge Vault entries must be permission controlled.

Minimum requirement:

* User can only see entries they created or entries allowed for their organization/workspace.
* Public Ora visitors must not access Knowledge Vault.
* Knowledge Vault should require authentication.
* No anonymous user can save or read Knowledge Vault entries.

Do not expose Knowledge Vault through public Ora routes.

Success Criteria

Phase 8A is complete only when an authenticated user can:

* Save a report to Knowledge Vault
* Save a lesson learned
* Save a corrective action
* Search saved entries
* Filter saved entries
* View entry details
* Edit an entry
* See version history
* Archive an entry
* Restore an archived entry

without any autonomous learning, prompt injection, semantic search, or vector retrieval.

The goal is to build the safe foundation first.
