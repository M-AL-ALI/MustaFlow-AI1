Start Phase 3A — Orax Desktop MVP Installer + Real Pairing Flow

Goal:
Move Orax from internal architecture into a usable first desktop workflow:
Website → Download/Install Orax Desktop → Sign in → Register desktop host → Pair mobile/website → See online status → Open project workspace.

This phase is about making Orax usable by a real user, not adding more hidden backend machinery.

Do not touch:
Ora, public-ai chat, AI Builder, credits, normal Ora project chat.

Current state:
Orax already has:
- desktop app skeleton
- host registration
- paired device tables
- relay actions
- project/thread model
- safe file read/draft/apply/verify/fix loop
- web/mobile Orax workspace pieces

Problem:
The flow is still too developer-ish. Users need a clean Codex-like setup experience.

Build:

1. Orax Desktop first-run flow
In `artifacts/orax-desktop`:
- Add polished first-run screens:
  - Welcome to Orax
  - Sign in with MustaFlow AI
  - Register this computer
  - Choose default permission mode
  - Ready screen with host name + connection status
- Do not ask user for password inside desktop.
- Use browser-based sign-in / token flow placeholder if full auth is still deferred.
- Make clear copy:
  “Orax Desktop lets MustaFlow AI work with projects on this computer after your approval.”

2. Host status reliability
Desktop should clearly show:
- Signed out
- Registering
- Online
- Offline/reconnecting
- Pairing available
- Error state

Website/mobile should show the same status.

3. Pairing flow
Implement real pairing UX on desktop, website, and mobile:
- Desktop can generate pairing code / QR payload.
- Mobile/website can redeem pairing code.
- Pairing code expires.
- Pairing code is account-bound.
- Already paired devices show as trusted devices.
- Revoked devices lose access.

Relevant existing backend:
- `/api/orax/pairing-codes`
- `/api/orax/pairing-codes/redeem`
- `/api/orax/hosts`
- `oraxPairingCodesTable`
- `oraxPairedDevicesTable`

4. Website Orax product page
Improve `/orax-product`:
- Show official Orax logo
- Clear Download Orax Desktop CTA
- Explain:
  - desktop app runs local work
  - web/mobile are remote control
  - user stays in control with approvals
- If build artifact is not ready, keep CTA disabled but visually professional:
  “Desktop installer coming soon”
- If installer path exists, wire button to it.

5. Orax card behavior
On website home/mode select:
- If no desktop host exists → Orax card opens `/orax-product`
- If desktop host exists but offline → open `/orax/devices`
- If desktop host online → open `/orax/workspace`
- Show small status badge:
  - Desktop online
  - Desktop offline
  - Setup required

6. Desktop projects screen
Make desktop Projects screen useful:
- list cloud Orax projects
- list local folders bound to those projects
- button: Add local folder
- button: Reconnect missing folder
- show `.orax/project.json` binding status
- never show unavailable folder as active

7. Security / permission mode UI
Desktop settings should expose permission mode:
- Read only
- Ask everything
- Ask risky (default)
- Trusted project
- Full access
- Custom

For now, if modes are not fully enforced, UI must clearly show what is active and what is still coming soon.

8. Website/mobile device management
Improve `/orax/devices` and mobile Orax connection card:
- show host name
- platform
- online/offline
- last seen
- permission mode
- paired devices
- revoke device
- test connection
- create pairing code
- cancel pairing code

9. Tests / wiring guards
Update `orax-wiring.test.ts`:
- desktop first-run screens exist
- no password collection in desktop
- pairing code generation exists on desktop UI
- pairing code redeem exists on mobile and website
- Orax card routes to product/devices/workspace based on host status
- permission mode labels exist
- no Ora/public-ai route usage

All clean. Push to GitHub.
