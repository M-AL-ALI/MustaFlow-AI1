Clarification: users are complaining about Ora “thinking” too long before the answer starts, especially in Instant / Free mode. They are not mainly complaining about word-by-word streaming style.

Please do not make major routing/model changes yet.

First, review the recent streaming change:
- If it changed the visual feel in a bad way, restore the old smooth word-by-word presentation.
- But do NOT restore any behavior that waits for the full model answer before showing the first words, because that would make the thinking delay worse.
- Keep privacy-safe timing diagnostics.

Main task: diagnose and reduce pre-answer latency for normal Ora text chat, especially Instant mode.

Measure these buckets:
1. client request received
2. auth/session resolved
3. tier/quota resolved
4. memory/context loaded
5. routing decision complete
6. provider request started
7. first provider token received
8. first visible client output
9. response complete

Focus on Instant / Free mode:
- short prompt
- normal prompt
- Arabic prompt
- memory-enabled prompt
- prompt that should not use web search

Do not change route decisions yet. Instead look for safe speed wins:
- Cache user tier/session briefly so every message does not redo slow account checks.
- Put strict timeout on memory/context loading in Instant mode; if memory is slow, answer first and use lighter context.
- Do not let memory save/extraction block the answer.
- Avoid unnecessary web search unless clearly requested/current.
- Keep Instant replies concise with smaller output limits.
- Make sure the client sends the request immediately and does not wait on account sync or UI state.
- Check DB pool/cold-start delays.
- Check provider first-token latency separately from our pre-processing.

Goal:
Instant mode should feel fast. The first answer should begin quickly. Quality should remain solid, but Instant should not wait for heavy context/routing/search work unless required.

Acceptance:
- Short Instant prompt starts visibly fast.
- Free and paid Instant mode both feel responsive.
- No raw prompt/memory text in logs.
- Routing behavior is unchanged unless diagnostics prove routing is the slow bucket.
- If old streaming feel is preferred, restore the visual pacing only, not the old full-answer buffering.
