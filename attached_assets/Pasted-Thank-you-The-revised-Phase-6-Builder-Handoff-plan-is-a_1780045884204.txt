Approved direction:

2. Do not quote raw user message in deterministic fallback
    The fallback currently says:

summary: "Visitor described: \"[truncated last user message]\""

That can violate the privacy rule because it may copy raw personal text, private details, or sensitive wording directly into the handoff.

Please change the fallback to a safer structure.

Recommended fallback:

{
  "summary": "Visitor wants to continue an idea from Ora inside the MustaFlow Builder.",
  "appIdea": "Start a new MustaFlow project based on the visitor's current idea.",
  "keyFeatures": [],
  "suggestedNextStep": "Describe your idea in the Builder and click Build.",
  "source": "ora_public_handoff"
}

If you do use the last user message, it must be sanitized aggressively:

* remove names/emails/phone numbers
* strip file names, URLs, IDs, refs
* truncate heavily
* do not wrap as a direct quote
* do not include sensitive or personal content

3. In-memory handoff store limitation must be documented
    Using an in-memory Map is acceptable for initial Phase 6 if the deployment is single-process and low-risk.

But please document the limitation:

* handoff tokens are lost if the API server restarts
* handoff tokens may fail if the app runs multiple server instances without sticky routing/shared storage
* anonymous sign-up flows that take longer than the TTL will expire
* future production scaling may require Redis, database TTL table, or another shared short-lived token store

For Phase 6, in-memory is acceptable only if you include a graceful expired-token message and the user can continue manually.

4. Consider TTL of 15 minutes
    12 minutes may be too short if the user signs up and verifies email.

Recommended:

* 15 minutes minimum
* possibly 20 minutes if Clerk email verification is commonly needed
* still single-use
* still consumed immediately after exchange

Please choose a TTL and explain why.

5. Token in URL still needs cleanup
    Even though the token is opaque, it is still a bearer token.

* token is never logged raw
* token is never stored in localStorage
* token is not sent to analytics
* token is only kept in memory/session flow long enough to exchange
* expired/used token gives safe message
