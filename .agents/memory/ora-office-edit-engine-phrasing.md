---
name: Ora Office edit engine phrasing gate
description: When the layout-preserving Office edit engine triggers vs silently falling back to full regeneration; how to smoke-test it.
---

The layout-preserving Office edit engine (`tryApplyLayoutPreservingFileEdit`, called first inside the `file_generation` tool branch of the Ora chat route) is pattern-based, not AI-based. If its regex intent parser fails OR the parsed old-text is not found in the package, it returns null and the request **silently falls back to the professional file generator**, which regenerates a brand-new branded deck/doc — original layout lost, no error surfaced.

**Why:** Prod verification of the edit engine showed "Replace the text Old Pricing with X on slide 1" regenerated a 4-slide branded deck instead of editing. The unquoted pattern captured `the text Old Pricing` as the search string (filler words included), found no match in slide XML, and fell back. The quoted form `Replace "Old Pricing" with "X" on slide 1` hit the engine and produced a perfect layout-preserving edit.

**How to apply:**
- When smoke-testing edits, use quoted phrasing (`replace "A" with "B"`) or minimal unquoted (`replace A with B`) — never `replace the text A ...`.
- A regenerated output is recognizable by: new title-case filename (not `<original>-edited.<ext>`), "Generated by Ora AI - MustaFlow" footer text, and different slide/section count. `-edited` filenames = real engine.
- Successful edits do NOT mutate the session-stored upload; each edit re-derives from the original package.
- Known product gap to fix eventually: strip filler prefixes ("the text", "the words", "the title") in `parseTextReplacement`, and consider falling back with a clarification instead of silent regeneration.
