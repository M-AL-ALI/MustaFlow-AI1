Approved direction: Build true realtime Talk to Ora.

Use website first, then mobile.

Default model: use gpt-realtime-mini only if it was verified with the current OpenAI key. Keep ORA_REALTIME_MODEL as an env override so we can switch to gpt-realtime / another supported realtime model without code changes.

Required corrections / guardrails:

1. Mic must stay separate.
Mic remains dictation only:
record voice → /transcribe → transcript into composer → user manually sends.

2. Talk to Ora must stop using the old loop as the primary path.
Current old loop:
record → /transcribe → /chat → /tts → play MP3 → restart.
Keep this only as fallback.

3. Backend must mint ephemeral realtime credentials.
Never expose OPENAI_API_KEY to website or mobile.
Use backend endpoint:
POST /api/public-ai/realtime/session

4. Follow the current OpenAI GA Realtime flow.
Use client secrets / ephemeral credentials from backend.
Use WebRTC for browser/mobile audio.
Use the GA Realtime session/event shapes, not deprecated beta headers.

5. Website first.
Build and test realtime Talk to Ora on website first because it does not require a native build.
Once website works, port same state machine to mobile.

6. Mobile needs native build.
react-native-webrtc or equivalent native realtime audio layer means hot reload alone is not enough.
A new dev/TestFlight build will be required before iPhone testing.

7. Same Ora rules must apply.
Realtime voice must preserve:
- anonymous sessions
- signed-in sessions
- tier resolver
- free/core/wave limits
- temporary chat
- memory/history settings
- selected language
- project/conversation context
- Ora isolation from Builder

8. Add diagnostics before calling it done.
Settings should show:
- realtime enabled
- realtime session created
- client secret received
- WebRTC connected
- mic stream active
- assistant audio received
- transcript events received
- interruption supported
- fallback used
- last realtime error

9. Acceptance is real behavior, not just code.
Must test:
- website browser
- real iPhone
- AirPods/Bluetooth
- anonymous
- signed-in Core account
- free/core/wave tiers
- interrupt while Ora is speaking
- mute/unmute
- end session
- network drop/reconnect
- fallback to old voice loop
