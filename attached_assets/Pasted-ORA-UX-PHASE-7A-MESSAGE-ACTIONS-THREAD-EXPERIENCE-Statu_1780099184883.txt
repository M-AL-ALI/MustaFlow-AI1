ORA UX PHASE 7A — MESSAGE ACTIONS + THREAD EXPERIENCE

Status: Approved for implementation.

Goal:
Make Ora feel like a polished, production-grade AI assistant similar to ChatGPT, Claude, and Perplexity while keeping all existing Phase 1–6 functionality intact.

PART 1 — MESSAGE ACTIONS

Create a reusable component:

* ora-message-actions.tsx

Actions by message type:

Assistant Message:

* Copy
* Download Markdown
* Read Aloud
* Retry / Regenerate
* Continue in Builder

User Message:

* Copy
* Edit & Resubmit

Dataset Analysis:

* Copy Summary
* Download Markdown Report
* Download JSON
* Download CSV Action Plan

Image Analysis:

* Copy
* Download Markdown
* Read Aloud
* Continue in Builder

Document Analysis:

* Copy
* Download Markdown
* Read Aloud
* Continue in Builder

Requirements:

* No backend routes
* No database changes
* No OpenAPI changes
* No billing changes
* No Knowledge Vault integration
* No project creation
* Downloads generated client-side only
* Strip internal refs before export:
    * imageRef
    * fileRef
    * datasetRef
    * session tokens
    * handoff tokens
    * internal metadata

UI:

* Show actions on hover (desktop)
* Show actions on tap/menu (mobile)
* Use compact GPT-style action row
* Keep clean and minimal

PART 2 — THREAD EXPERIENCE

Add GPT-style conversation usability improvements.

Features:

1. Smart Auto Scroll

* Auto-scroll when user is already near bottom
* Do not force-scroll while reading older messages

2. Jump To Latest Button

* Floating button appears when user scrolls away from newest message
* One tap returns to bottom

3. Previous Message Navigation

* Smooth scrolling through long conversations
* Preserve position

4. Session Restore

* Restore current conversation after refresh
* Do not lose active thread accidentally

5. Mobile Improvements

* Better thread scrolling
* Better touch behavior
* Better message spacing

PART 3 — POLISH

Dynamic Atom:

    * Idle

Ora Avatar:

Current icon feels temporary.

Create a more professional Ora identity:

* Dynamic atom concept

PART 4 — EXPORT EXPERIENCE

Add conversation export options:

* Export conversation as Markdown
* Export conversation as JSON

* Client-side generation
* No server storage
* No transcript logging
