All three Talk to Ora bugs are fixed and pushed to GitHub (881d5d4d). Here's a summary of what was applied identically to both the web hook (use-ora-realtime-voice.ts) and mobile hook (useOraRealtimeVoiceNative.ts):

Bug 1 — Stuck in "thinking" indefinitely
Added a 15-second thinkingWatchdogRef timer. It starts when the state enters "thinking" (speech_stopped / response.created), resets if response.created fires again on an overlapping turn, clears immediately when audio arrives (output_audio_buffer.started) or the reply completes (response.done). If neither ever fires — because the data-channel message was dropped — the watchdog fires after 15 s, logs thinking_watchdog_timeout, and recovers the session to "listening".

Bug 2 — Glitched/incomplete audio + no error recovery

OUTPUT_STOP_DEBOUNCE_MS raised 350 → 600 ms so multi-chunk OpenAI audio buffer cycles don't trigger a premature "stop → listening" flip mid-sentence.
Added error event recovery in both hooks (mobile had no error case at all). When a model error arrives mid-response, both assistantResponseActiveRef and assistantSpeakingRef are cleared, both timers cancelled, and state recovers to "listening" so the session stays usable.
Bug 3 — Stops listening/responding after a couple turns
lastAcceptedUserTurnAtRef is now refreshed in response.done with Date.now(). The 4-second speaker-focus follow-up window reopens from the moment Ora finishes speaking, not from the last accepted user turn — so casual replies like "that's great" or "continue" work naturally right after a long Ora response without needing a wake word.
