Main correction:

Do not pass the actual idea summary directly in the URL as ?idea=....

That can expose the visitor’s idea in:

* browser history
* analytics
* server logs
* referrer headers
* screenshots
* shared links

Instead, use a short-lived opaque handoff token.

Approved direction:

Ora should help the visitor, then when the visitor clicks “Continue in MustaFlow Builder,” the system creates a sanitized text-only handoff summary and stores it temporarily behind an opaque token.

Flow should be:

1. Visitor chats with Ora
2. Visitor clicks “Continue in MustaFlow Builder”
3. Public route creates sanitized text-only handoff summary
4. Public route returns short opaque token only
5. Visitor is redirected to sign-in/sign-up with ?handoff=<token>
6. After login, protected Builder route exchanges the token
7. Builder opens a new project/start screen with the sanitized summary pre-filled
8. Token is consumed and deleted/expired
9. Raw files/images/datasets/audio/session tokens are never transferred

Recommended routes:

Public route:

* POST /api/public-ai/handoff/create
* no login required
* accepts limited recent Ora messages or server-safe summary input
* creates sanitized summary
* stores it temporarily or signs it securely
* returns opaque token only
* cannot create projects
* cannot access Builder
* cannot import project/user/secret/credit models

Protected route:

* POST /api/builder/handoff/exchange
* requires authenticated user
* validates token
* consumes token
* returns sanitized summary to Builder
* may prefill Builder idea input or create a draft starter message only after authentication

Important security rules:

* Public Ora route must never create projects
* Public Ora route must never access Builder/project files/databases/secrets
* Public Ora route must never transfer raw file contents
* Public Ora route must never transfer raw images/base64
* Public Ora route must never transfer raw datasets
* Public Ora route must never transfer audio
* Public Ora route must never transfer full unfiltered transcript
* Only sanitized text summary may cross into Builder
* Handoff token must expire quickly, recommended 10–15 minutes
* Handoff token must be single-use
* Token must not expose the summary itself
* No user secrets, private uploads, or fileRefs should be included
* If handoff creation fails, show a safe fallback: “Please sign in and describe your idea in the Builder.”
