The remaining blocker is now specific:

The agent loop’s inline run_command calls are being killed by Fly autostop before the loop can finish. Because of that, the task never reaches file commits, file_diff events, check_result chips, preview refresh, real app preview, or final summary.

Please stop treating this as an npm or TypeScript issue. The deeper issue is the runtime execution model during active agent tasks.

We need one focused fix:

Agent-loop inline command execution must be protected from Fly autostop.

Please evaluate and recommend the safest option:

Option A — Disable Fly autostop while an agent task is active
When an agent task starts:

* keep the machine running
* prevent autostop during run_command/pkg_install/check/build/preview steps
* re-enable autostop after the task completes/fails/cancels

This is likely the cleanest short-term fix if Fly supports it.

Option B — Add active-task HTTP keepalive
During an active build:

* keep a lightweight HTTP server/health endpoint alive
* ping it during long execs
* prevent Fly from thinking the machine is idle
* stop keepalive after task completion

Option C — Convert run_command to background job + polling
For long commands:

* start command in background
* write stdout/stderr/status to files
* poll status using short exec calls
* recover after machine restart by resyncing files and rerunning only when safe

Option D — Move build/test/check commands to a separate stable worker
Use Fly container only for preview, while a build worker handles:

* npm install
* tsc
* vite build
* tests
* quality gate

This may be the best long-term design, but it is larger.
