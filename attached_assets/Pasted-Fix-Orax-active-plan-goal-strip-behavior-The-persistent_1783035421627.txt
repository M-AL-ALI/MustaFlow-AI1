Fix Orax active plan/goal strip behavior. The persistent bottom “PLAN MODE / Continue” strip is not Codex-like and creates duplicate actions.

Problem:
In the Orax chat, the thread already shows an inline action button such as “Check changes”, but the composer area also shows a persistent “PLAN MODE ... Continue” strip. This is confusing and not Codex-like.

Expected behavior:
Orax should have one clear next action at a time, inline in the chat thread.

Required changes:

1. Hide the bottom active plan/goal strip when there is already an inline action suggestion visible in the thread.
Examples:
- If the assistant message shows “Check changes”, do not also show bottom “Continue”.
- If the assistant message shows “Start implementation”, do not also show bottom “Continue”.
- If approval action is visible, do not also show bottom “Continue”.

2. The plan/goal strip should be informational only, not a competing primary control.
If kept, it should only appear when:
- there is active plan/goal state,
- there is no visible inline action,
- the task is actually waiting for a generic continue.

3. Fix stale context in the strip.
The strip currently shows an old task goal like “Review this repository and expla...” while the current user says “Fix it”.
The strip should always reflect the selected task’s current active goal/plan, or hide if it is stale.

4. Prefer inline thread actions over composer-strip actions.
Codex-like behavior:
- Assistant says what it did.
- Assistant shows the next action inline.
- User taps that inline action or sends a message.
No duplicate bottom workflow buttons.

5. Website and mobile must match.
Apply the same behavior to:
- artifacts/mustaflow/src/pages/orax.tsx
- artifacts/ora-mobile/app/(home)/orax.tsx

6. Add wiring tests:
- When inline action/suggestion exists, active plan strip should not render a Continue button.
- Plan strip only renders when active plan/goal exists and no inline action is visible.
- Web and mobile use the same condition.
- No raw workflow IDs.
- No Ora/public-ai/project-chat/credits wiring.

Run:
