Additional implementation safeguards for #1445 — Ora Live Response Streaming

Add these requirements before implementation starts:

1. Do not remove the existing non-streaming endpoint.
    Streaming should become the preferred path, but /api/public-ai/chat must remain as a fallback. If /chat/stream fails before first token, the frontend should silently retry once using the existing non-streaming endpoint.
2. Add a feature flag.
    Add ORA_STREAMING_ENABLED=true/false.
    If disabled, Ora should automatically use the existing non-streaming flow. This gives us a safe rollback path if streaming causes issues in production.
3. Prevent proxy buffering.
    For SSE responses, set:

* Content-Type: text/event-stream
* Cache-Control: no-cache, no-transform
* Connection: keep-alive
* X-Accel-Buffering: no

Also make sure compression does not buffer the stream. Tokens must flush as they are written.

4. Stream adapter design.
    Create a clean provider streaming adapter instead of hardcoding streaming logic directly inside the route.

Preferred shape:

* streamOraMessage(...)
* returns an async generator
* yields typed events: start, status, token, done, error

Provider-specific streaming should stay behind this adapter so OpenAI, Gemini, Claude, and DeepSeek can be handled cleanly.

5. Abort handling.
    If the browser disconnects, the backend must cancel the provider request and stop writing to the response.
    Use req.on("close") and an AbortController.
6. Save final answer once.
    The final assistant message should be saved only once, after the stream completes.
    Do not save every token.
    Do not create duplicate assistant messages.
    If a stream fails after partial tokens, mark the message as partial/error state but preserve the text.
7. Session limits must count once.
    One user message = one message count.
    Do not count every token as a message.
    Do not double-count if fallback to non-streaming happens after streaming fails before first token.
8. SSE event format must be strict.
    Every SSE event should follow this format:

event: token
data: {“text”:”…”}

Use JSON-safe encoding.
Never write raw text directly into SSE without JSON encoding.
Never allow raw SSE artifacts to appear in the UI.

9. Add timeout guards.

* 30 seconds with no token = stream error + retry UI.
* Provider timeout before first token = fallback to next provider or non-streaming endpoint.
* Provider timeout after partial tokens = preserve partial response and show retry.

10. Markdown streaming must be stable.
    Do not over-render markdown on every character if it causes jitter.
    Use a debounced render or safe incremental renderer.
    Partial code fences, lists, and tables must not visually break the message.
11. Add production benchmark metrics.
    Streaming benchmark must report:

* TTFB: time to first byte
* TTFT: time to first token
* total generation time
* token throughput
* stream completion rate
* fallback rate
* mid-stream error rate
* duplicate-message count
* stuck-thinking count

12. Keep Ora isolation enforced.
    The existing Ora isolation quality-gate test must remain passing.
    No SSE event, status string, UI label, test fixture, benchmark prompt, or route should reintroduce:

* AI Builder
* MustaFlow Builder
* handoff
* handoffCta
* builder_handoff
* Continue in Builder
* ready to build
* open in Builder
* builder/handoff

13. Rollout rule.
    Implement in this order:
14. Backend SSE route with mocked/test stream
15. Provider streaming adapter
16. Frontend streaming consumer
17. UI animation/cursor
18. Error/retry handling
19. Scroll behavior
20. Accessibility/reduced-motion
21. Tests
22. Benchmark
23. Live audit

Do not ship frontend animation only. The requirement is real backend token streaming.
