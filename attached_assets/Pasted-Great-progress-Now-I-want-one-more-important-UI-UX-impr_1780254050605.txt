Great progress. Now I want one more important UI/UX improvement for the Agentic AI Builder chat experience.

The agent must show real live action text in the Builder message thread while it is building.

I want users to clearly see what is happening step by step, similar to an activity timeline, but inside MustaFlow AI Builder chat.

This should not be fake loading text.
It must be powered by the real SSE/task events from the agent loop.

Goal:
When the user sends a prompt and the agent starts building, the AI response/message should show a live action timeline at the bottom of the active message thread.

Example user prompt:
“Build me a booking app with login, admin dashboard, booking form, customer list, and database test records.”

The AI message should show live steps such as:

🧠 Planning the app structure
📂 Reading project files
🧱 Creating frontend pages
📝 Writing src/App.tsx
📦 Installing required package
🗄️ Creating database schema
💻 Running command
🧪 Running checks
👁️ Refreshing preview
🛠️ Fixing preview error
💾 Saving checkpoint
✅ Build check passed
⚠️ Waiting for your approval
🚀 Ready for testing / deployment preparation

Requirements:

1. Show real action text live inside Builder chat
   The active AI message should include a live “Working…” timeline at the bottom of the message bubble or directly underneath it.

Do not only show this in Developer Mode.
Do not only show it in logs.
Do not hide it in a progress bar.

This must be visible to normal non-technical users inside AI Builder.

2. Use icons for each step
   Each action should have a simple icon so users can quickly understand what is happening.

Suggested icon mapping:

* Planning: Brain or Sparkles
* Reading files: Folder/Search
* Writing files: Pencil/Edit/Code
* Installing package: Package
* Database/schema: Database
* Running command: Terminal
* Testing/checking: CheckCircle/TestTube
* Preview refresh: Eye/Monitor
* Fixing error: Wrench
* Approval needed: Shield/Lock
* Checkpoint saved: Save/History
* Deployment prep: Rocket
* Error/blocked: AlertTriangle
* Done: CheckCircle

Use existing icon library if available, such as lucide-react.

3. Use actual event types
   Map the timeline to real event types, such as:

* narration
* reading_files
* generating_code
* tool_call
* command_output
* file_diff
* check_result
* agent_prompt
* preview_refresh
* checkpoint
* failed
* completed

If an event does not have a friendly label, convert it to a user-friendly label.

Example:
Raw: pkg_install npm react-router-dom
User sees: “Installing router package”

Raw: file_diff src/App.tsx
User sees: “Updated app layout file”

Raw: check_result typecheck passed
User sees: “TypeScript check passed”

4. Keep it simple for non-technical users
   Default view should be plain English.

Do not overwhelm users with raw terminal logs by default.

Example default:
“Installing required packages…”

Expandable advanced details:
“npm install react-router-dom”

5. Make the timeline compact but useful
   The timeline should not take over the whole chat.

Show the latest 5–8 actions by default.
Allow expand/collapse to see more steps.
Older completed steps can collapse into a summary.

Example collapsed summary:
“12 steps completed — files written, checks run, preview refreshed.”

6. Show status for each action
   Each step should have a visible status:

* Pending
* Running
* Completed
* Waiting for approval
* Failed
* Retrying
* Skipped

Use visual states:

* Running = pulse/spinner
* Completed = checkmark
* Failed = warning/error icon
* Waiting approval = shield/lock icon
* Retrying = circular arrow

7. Place it near the bottom of the active chat message
   The user should see the current action near the bottom of the current AI response/message thread.

The layout should feel like:

AI response text:
“I’m building your booking app now.”

Live build timeline:
🧠 Planning structure...
📂 Reading files...
📝 Writing booking form...
📦 Waiting for approval to install package...

Steering input:
“Steer the build…”

Approval card if needed:
Approve / Deny

This keeps the user focused inside the chat thread.

8. Handle auto-scroll correctly
   The chat should auto-scroll to the latest action only if the user is already near the bottom.

If the user scrolls up, do not force-jump them down.
Show a “Scroll to latest” button.

This is important because users may be reading earlier steps while the agent continues working.

9. Connect to preview status
   When preview refreshes or changes, the timeline should show it.

Examples:
👁️ Preview refreshed
⚠️ Preview error detected
🛠️ Fixing preview error
✅ Preview running

The user must understand that the app preview is updating because of real file changes.

10. Final state after task completion
    When the task completes, collapse the live timeline into a clean final build summary.

Final summary should show:

* Files changed
* Packages installed
* Database changes
* Checks passed/failed
* Preview status
* Checkpoint saved
* Remaining blockers
* Suggested next step

11. Do not fake progress
    Every step must come from real events.

If the agent is waiting for approval, show that clearly.
If the task fails, show the real reason.
If package install fails, show a simple explanation with expandable technical detail.

12. Add a live UI verification
    After implementing this, run a UI verification from normal AI Builder, not Developer Mode.

Verify:

* Timeline appears under active AI message.
* Icons appear for each action type.
* Steps update live while agent runs.
* Approval prompt appears inside chat.
* File-change steps appear.
* Check-result steps appear.
* Preview refresh step appears.
* Failed steps show warning icon.
* Completed task collapses into summary.
* Auto-scroll behaves correctly.
* “Scroll to latest” appears when user is not at the bottom.

Important:
This is not just cosmetic. This is part of the agentic user experience.

Users need to see the AI actually planning, reading, building, installing, testing, fixing, and updating the preview in real time.
