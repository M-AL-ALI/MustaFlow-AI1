“Please improve Ora Mobile and Ora Website image handling and Talk to Ora poor-network resilience. First, generated images must be easy to save. On mobile, every generated image card should open a full-screen image preview when tapped, with clear actions: Save to Photos, Share, Copy link, and Close. Use expo-media-library / expo-file-system to download the image or decode base64, request photo-library permission only when the user taps Save, then call MediaLibrary.saveToLibraryAsync() and show a success/error toast. If permission is denied, show a clear message and keep Share available. On website, generated images should have visible Download / Open / Copy link actions and should still work after reload using the durable asset/download URL. Second, uploaded images should render as visual thumbnail cards in the chat thread, not just filename text. When a user attaches an image, show a local thumbnail immediately before upload finishes; after upload, replace it with the uploaded asset preview. The chat message should preserve the image preview after reload/history restore using imageRef/assetId/download URL where available. This should work on both mobile and website, and match ChatGPT/Codex-style behavior: image thumbnail, filename, status, and tap-to-preview. Add tests proving generated image save/share actions exist on mobile, uploaded image messages render thumbnails, and reloaded conversations keep image previews when asset metadata exists.
For Talk to Ora, please make it network-resilient instead of visually glitchy in poor service areas. Poor internet cannot be made perfect, but the app must degrade gracefully. Add mobile network/session diagnostics and recovery around the realtime WebRTC session: listen to connectionState, iceConnectionState, data channel open/close/error, audio start/stop, response created/done/error, and network reachability changes. If the connection becomes poor/disconnected, keep the Talk to Ora card layout stable, show a small ‘Connection unstable, reconnecting…’ state, stop accepting new turns temporarily, and attempt reconnect with exponential backoff. If reconnect succeeds, return to listening automatically. If reconnect fails after a short limit, show a clear Retry button and offer text chat fallback. Do not let the UI card resize, change style, or jump around based on connection state; reserve stable dimensions and only change the status text/icon. Add watchdogs so ‘thinking’ or ‘speaking’ cannot stay stuck forever when packets/data-channel events are lost. If the user is in a bad network area, Ora should either recover or clearly say the connection is unstable, not appear broken. Apply this to both mobile and website Talk to Ora where applicable, but prioritize mobile because users reported it there. Add QA diagnostics in Settings showing last realtime connection state, reconnect count, last error, last disconnect reason, and whether the session recovered. Manual QA should include airplane-mode toggle, weak Wi-Fi/cellular simulation, background/foreground, and moving from bad network to good network; the UI should stay stable and the session should recover or show Retry cleanly.”
