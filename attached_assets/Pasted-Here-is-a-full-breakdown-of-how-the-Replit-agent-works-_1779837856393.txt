Here is a full breakdown of how the Replit agent works, from the moment you type a prompt to the moment code appears:

1. You send a prompt

You type something like "build me a todo app." That text goes to Replit's backend as a regular API request.

2. The backend feeds it to an LLM

Replit sends your prompt to a Large Language Model (like GPT or a similar model) along with a system prompt that gives the AI context — things like:

What files already exist in your project
What your previous messages said
What tools the agent is allowed to use
3. The agent has tools, not just text

This is the critical part. The agent is not just generating text — it is given a set of tools it can call, such as:

read_file — read an existing file
write_file — create or overwrite a file
run_shell_command — execute a terminal command
search_files — find relevant code
The LLM decides which tool to call, with what arguments, and in what order — based on your request.

4. A loop runs until the task is done

The agent runs in a loop called an agentic loop:

Receive prompt
      ↓
LLM thinks → decides to call a tool
      ↓
Tool executes (real file write, real shell command)
      ↓
Result fed back to LLM
      ↓
LLM thinks again → call another tool or finish
      ↓
Repeat until done
This loop keeps running, with the LLM seeing the results of each action and deciding what to do next — just like a developer would think, act, check the result, and continue.

5. Real side effects in the real container

Every tool call has real consequences in your container. When the agent calls write_file, the actual file changes on disk. When it runs npm install, packages actually get installed. It is not a simulation.

6. The preview updates as a side effect

As covered earlier — because the dev server is watching the filesystem, every file the agent writes automatically triggers a hot reload in your preview. The agent does not control this; it just happens.

Why is it designed this way?

Tool use makes it an agent, not just a chatbot. A chatbot only produces text. An agent produces text and takes actions with real consequences.
The loop allows multi-step reasoning. Complex tasks like "build a full-stack app" require dozens of steps. The loop lets the AI plan, execute, observe, and adapt — rather than trying to do everything in one shot.
Grounding in real files keeps it honest. By reading actual files before writing, the agent always works from the true current state of your project — it cannot hallucinate what your code looks like.
In short: Replit's agent is an LLM wrapped in a loop that can read and write your actual project files, run real commands, and observe the results — turning a conversation into working software.
