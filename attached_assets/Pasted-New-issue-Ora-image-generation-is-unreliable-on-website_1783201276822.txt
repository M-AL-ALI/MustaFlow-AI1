New issue: Ora image generation is unreliable on website and mobile.

User reports:
1. Ora sometimes does not generate an image/picture when explicitly asked.
2. Ora sometimes creates a file instead of an image.
3. Users need to ask multiple times before Ora routes to inline image generation.
4. Sometimes generated images do not match the user’s request closely enough.
5. This must work on both website Ora and Ora Mobile.
6. Do not regress any already-fixed features: account sync, billing deep links, Talk to Ora, streaming word-by-word, file generation, memory, or legal/provider wording.

Important code finding:
routeOraMessage currently checks file generation before image generation. That can allow ambiguous “create/generate/make” requests to route incorrectly when a user says things like:
- “make me a picture”
- “create an image”
- “generate a poster”
- “make a flyer image”
- “create a photo for my business”
- “design a banner”
- “make a logo”
- “create a picture for Instagram”
Image intent must win unless the user explicitly asks for a downloadable file format such as PDF, DOCX, XLSX, CSV, or PPTX.

Required fixes:

1. Make image-generation routing deterministic
- In routeOraMessage(), explicit image-generation intent must be evaluated before generic file generation.
- Do NOT break explicit file requests:
  - “create a PDF report”
  - “make an XLSX budget tracker”
  - “generate a PowerPoint deck”
  - “export a CSV”
  must still route to file_generation.
- But these must route to image_generation:
  - “generate an image of a sunset”
  - “create a picture of a dog”
  - “make me a logo”
  - “design a poster”
  - “create a flyer image”
  - “make an Instagram post image”
  - “draw a cat”
  - “generate a photo-realistic product shot”
  - “create a banner for my website”
  - “make a thumbnail”
- Image lookup/search must remain separate:
  - “find official logo images”
  - “search for real photos”
  - “show me reference images”
  should route to search, not image_generation.

2. Add an explicit image-intent resolver
Create a single helper in orchestrator.ts such as:
resolveOraVisualIntent(message)
returning:
- "generate_image"
- "find_image"
- "generate_file"
- "none"

Priority:
A. Real/reference/source/official/find/search/look up -> search
B. Generate/create/make/draw/render/design/paint + image/picture/photo/logo/poster/flyer/banner/icon/thumbnail/illustration/artwork/scene/portrait/mockup/social post -> image_generation
C. Explicit PDF/DOCX/XLSX/CSV/PPTX/export/download file -> file_generation
D. Otherwise normal chat

3. Harden file-generation detection
In detectFileRequest(), do not treat “image file”, “picture”, “photo”, “poster”, “flyer”, “logo”, “banner”, “thumbnail”, “illustration”, “art”, or “graphic” as file generation unless a real file format is explicitly present.
Example:
- “create a poster” -> image_generation
- “create a poster PDF” -> file_generation PDF
- “make a flyer” -> image_generation
- “make a flyer as PDF” -> file_generation PDF

4. Improve image prompt fidelity
In image-quality.ts, strengthen buildOraImageGenerationProfile() so every image prompt passed to the image model has:
- subject
- requested style
- composition/framing
- lighting
- background/setting
- aspect ratio
- quality tier
- negative constraints: no random text, no watermark, no extra limbs/faces, no irrelevant objects, do not ignore user’s exact subject
- if user gives exact constraints, preserve them exactly
- if user asks for text in an image/logo/poster, keep text minimal and warn that exact text rendering may vary if needed

The generated prompt should stay faithful to the user. Do not over-invent when the user is specific.

5. Add progress/status clarity on both platforms
Because image_generation specialist requests fall back from /chat/stream to /chat, the UI must not feel like Ora is stuck.
When stream endpoint returns:
{ streamingFallback: true, tool: "image_generation" }
both website and mobile should show a clear status:
“Generating image…”
not generic “thinking…”
Then replace it with the image card once imageUrl arrives.

6. Verify response contract
Backend /api/public-ai/chat image_generation response must always include:
- reply
- imageUrl
- imageId when editable/persisted
- imageCount/imageLimit usage fields
If image generation fails:
- refund image quota
- show a specific error:
  “Image generation failed. Please try again.”
not a generic file/chat error.
If provider is not configured:
- show “Image generation is temporarily unavailable.”
- do not pretend the image was generated.

- edit image button must still work when imageId exists
- image search gallery must remain distinct from generated image card
