Start Phase 3N — Orax Desktop Health Recovery Actions.

Goal:
Upgrade the Orax Desktop Health page from read-only diagnostics into an actionable recovery panel. Keep Ora untouched. This phase must only touch Orax Desktop, Orax desktop docs/scripts, and Orax wiring tests unless a very small API change is absolutely required.

Build:

1. Health page action buttons
In artifacts/orax-desktop/src/renderer/pages/HealthScreen.tsx, add contextual actions for each failing health area:

- Sign-in status:
  - If signed out, show "Sign in again"
  - Calls the existing desktop auth/sign-in flow
- Host registration:
  - If host is missing or offline, show "Reconnect host"
  - Calls the existing host registration/heartbeat path
- Relay polling:
  - If relay is idle/error, show "Restart relay"
  - Calls existing relay restart/status refresh logic
- Pairing readiness:
  - Show "Open pairing"
  - Navigates to the existing Pairing page
- Release channel:
  - Show "Check release status"
  - Re-runs the existing release/update status check if available; otherwise show a safe "Release channel configured" status
- Diagnostics export:
  - Keep "Export Support Diagnostics"
  - It must continue using the existing validated diagnostics exporter

2. Recovery result state
Add local UI state for action results:
- Running
- Success
- Failed
- Last attempted time
- Human-readable result text

Do not expose tokens, paths, env vars, or raw error dumps. Redact sensitive values before rendering errors.

3. Desktop IPC surface
If needed, add minimal IPC methods under the existing desktop bridge:
- health.refresh()
- health.reconnectHost()
- health.restartRelay()
- health.startSignIn()
Do not expose raw Node APIs to the renderer.
Do not add broad command execution.

4. AppContext integration
Reuse existing AppContext state where possible:
- auth/session
- host state
- relay state
- pairing/navigation
Avoid duplicate polling loops if existing state already exists.

5. Docs
Update docs/orax-desktop-update-recovery.md with:
- Health recovery actions
- What each button does
- What data is safe to export
- Manual smoke checklist for Windows

6. Readiness script
Update or add readiness checks so verify:phase3n confirms:
- HealthScreen has all recovery buttons
- IPC methods are present if added
- No Ora/public-ai references
- No token/password/env/path strings are rendered
- Diagnostics export still validates before writing

7. Wiring tests
Update artifacts/mustaflow/src/lib/__tests__/orax-wiring.test.ts with Phase 3N assertions:
- Health page includes "Sign in again", "Reconnect host", "Restart relay", "Open pairing", "Export Support Diagnostics"
- Health recovery actions use existing IPC/AppContext, not direct Node APIs
- No Ora/public-ai routes or useOraChat references
- No raw token/password/env/path rendering

Acceptance:
The installed desktop app Health page should tell the user what is wrong and provide a direct safe action to recover it, without touching Ora and without exposing secrets.
