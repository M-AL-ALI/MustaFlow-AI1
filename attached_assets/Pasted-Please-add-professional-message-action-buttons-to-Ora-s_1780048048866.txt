Please add professional message action buttons to Ora’s message thread, similar in behavior to modern AI chat apps, but with original MustaFlow/Ora styling.

Goal:
Ora messages should feel polished and useful. Visitors should be able to copy, edit, download, and reuse responses easily from the message thread.

Do not copy ChatGPT’s exact UI. Use it only as general inspiration. Build an original MustaFlow/Ora design using our own spacing, colors, icons, and Dynamic Atom/Ora styling.

1. Add message action toolbar

Create a reusable component:

OraMessageActions

It should render small action buttons near each message.

Recommended icons:

* Copy — copy message text
* Edit — edit user message and resend
* Download — download message/report/analysis
* Read aloud — for assistant responses if TTS is available/enabled
* Retry / Regenerate — for assistant messages if safe
* Continue in Builder — only where handoffCta applies

2. Where buttons should appear

Desktop behavior:

* show actions on hover over a message
* also show actions when message is focused by keyboard
* keep layout clean and not cluttered

Mobile behavior:

* show actions after tapping the message or tapping a small “more” button
* avoid showing too many icons all the time
* use a compact bottom action row or small popover

3. User message actions

For user messages, show:

* Edit
* Copy

Edit behavior:

* clicking Edit loads that message back into the textarea
* user can modify it
* button changes to “Send edited message” or normal Send behavior can be reused
* after edited message is sent, remove or invalidate later assistant responses from that point in the local message thread, then generate a fresh Ora response
* preserve sessionStorage consistency

Important:
If the original user message included a temporary file/image/dataset attachment that has expired or been consumed, editing should not silently reuse the old attachment. Show a safe note:
“The original attachment may no longer be available. Please upload it again if needed.”

4. Assistant message actions

For assistant messages, show:

* Copy
* Download
* Read aloud if TTS is supported
* Retry / Regenerate if the message can be regenerated safely
* Continue in Builder if handoffCta is true and it is the latest applicable response

Copy behavior:

* copies clean message text to clipboard
* show small success toast: “Copied”
* no raw JSON copied unless user specifically chooses export JSON

Download behavior:
Allow downloading assistant responses as:

* .txt for normal answers
* .md for structured answers with sections
* .json for dataset/root-cause structured results, if useful
* .csv only when the response includes a simple table/action plan that can safely be exported

Recommended default:

* Download as Markdown for assistant responses
* Download as JSON for dataset analysis card only if user chooses “Download data”

5. Dataset/root-cause result actions

For dataset analysis cards, add actions:

* Copy summary
* Download report
* Download JSON
* Download action plan as CSV if an action plan table exists

The downloaded report should include:

* executive summary
* key findings
* KPI gaps
* Pareto findings
* root-cause analysis
* 5 Whys
* Fishbone categories
* recommendations
* action plan
* risks/limitations
* next steps

6. Image analysis actions

For image-analysis messages, show:

* Copy analysis
* Download analysis
* Read aloud
* Continue in Builder if applicable

Do not download or expose the original image from Ora unless the user already has it locally. Ora should not create permanent image links.

7. File/document analysis actions

For document-analysis messages, show:

* Copy answer
* Download summary/report
* Read aloud
* Continue in Builder if applicable

Do not download or expose the original uploaded file from Ora. Uploaded files remain temporary.

8. Voice transcript actions

For voice-originated user messages:

* show Copy
* show Edit
* optionally show a small label: “Voice transcript”
* editing should edit the transcript text only, not audio
* audio is not stored or replayed

9. Clipboard and download implementation

Use browser APIs:

* navigator.clipboard.writeText() for copy
* Blob + URL.createObjectURL() for download
* always URL.revokeObjectURL() after download to avoid memory leaks

If clipboard permission fails:

* show safe fallback message: “Copy failed. Please select and copy manually.”

10. Privacy and safety

Do not log:

* copied content
* downloaded content
* edited message text
* user prompt text
* assistant answer text

Do not store downloads on the server.
Downloads are generated client-side only.

Do not expose:

* fileRef
* imageRef
* dataset raw rows
* base64 image data
* session token
* handoff token
* private internal IDs
* Builder/project data

11. Accessibility

Each icon button must have:

* aria-label
* tooltip
* keyboard focus state
* visible hover/focus styling
* mobile tap target large enough

Example labels:

* “Copy message”
* “Edit message”
* “Download response”
* “Read response aloud”
* “Regenerate response”
* “Continue in MustaFlow Builder”

12. UI design recommendation

Use a subtle action row under or beside messages.

Desktop:

* assistant message actions can appear under the assistant bubble aligned left
* user message actions can appear near the user bubble aligned right
* icons should be small, clean, and low-contrast until hover/focus

Mobile:

* show a small “⋯” or action pill
* tapping opens Copy / Edit / Download / Read aloud actions

Keep the design premium and not busy.

14. Edit-message behavior details

When a user edits a previous message:

Option A — safer Phase 1 behavior:

* load message into textarea
* user edits and sends
* append it as a new message
* mark it as “edited from previous message”
* do not delete earlier thread

Option B — more ChatGPT-like behavior:

* replace the old user message
* remove all messages after it
* regenerate assistant answer

Recommendation:
Start with Option A because it is safer and does not risk breaking session state. Add Option B later if needed.

18. Scope control

This feature is UI/message experience only.

Do not add:

* server-side storage of downloads
* server-side export generation
* database persistence
* Builder project access
* Knowledge Vault learning
* analytics tracking of copied/downloaded content
* paid feature/billing logic

Final expectation:
