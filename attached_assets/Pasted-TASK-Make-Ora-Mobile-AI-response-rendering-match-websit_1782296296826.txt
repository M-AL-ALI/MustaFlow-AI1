5. Streaming behavior — this is critical

Website streaming source:
- use-ora-chat.ts consumeOraStream()
- POST /api/public-ai/chat/stream
- SSE events:
  - event: start
  - event: token
  - event: done
  - event: error

Website behavior:
- On token event:
  - read parsed.text
  - append delta to the current assistant streaming message
  - force React to commit immediately
  - then wait about 55ms before processing the next token
- This delay is intentional. It prevents all tokens from appearing at once when Replit/dev proxy batches SSE frames.
- The visible result should feel word-by-word / phrase-by-phrase.

Mobile must:
- Append each SSE token to the existing assistant message.
- Do not wait until done to show the reply.
- Do not batch all tokens into one final response.
- After appending a token, yield briefly so UI paints:
  - use small delay around 40–60ms, matching website’s 55ms.
- Keep isStreaming true until done event.
- On done event, patch final metadata into the same assistant message.

6. Streaming rich text behavior

Website source:
- ora-rich-text.tsx

Website behavior:
- Streaming text is sanitized before rendering:
  - If code fence ``` is unclosed, temporarily close it.
  - If bold marker ** is dangling, strip it.
- This prevents broken Markdown during streaming.
- New words fade in:
  - newly mounted word spans get 260ms fade animation.
  - old words do not re-animate.
- A blinking cursor appears at the end of the last streaming block.
- Screen reader behavior:
  - aria-live polite during streaming
  - off after streaming finishes

Mobile must:
- Sanitize partial markdown during streaming.
- Avoid showing raw dangling ``` or **.
- Add a subtle fade-in for newly appended words if possible.
- Add an end cursor while streaming if feasible.
- At minimum, streaming must visibly grow token-by-token and not flicker the whole message.

7. Stream error / fallback behavior

Website behavior:
- If /chat/stream returns 503 or streamingFallback before tokens:
  - silently fall back to /api/public-ai/chat
  - pass streamFallbackToken if present
  - do not double-charge quota.
- If SSE error happens after tokens:
  - keep partial content
  - mark streaming false
  - show error: “Ora's response was cut off. The partial reply above may be incomplete.”
- If user navigates/aborts:
  - abort stream
  - remove empty streaming placeholder if it has no content
  - do not show error.
- If provider does not truly stream:
  - mark viaFallback / Non-streamed only in dev monitoring.

Mobile must mirror this behavior.
