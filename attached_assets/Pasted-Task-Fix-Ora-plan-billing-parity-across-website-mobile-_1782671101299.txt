Task: Fix Ora plan/billing parity across website + mobile, keep payments website-managed, and isolate Ora plan features from AI Builder features.

Goal:
Ora mobile and Ora website must show the same Ora-only plan tiers, prices, features, and unlock behavior. Payments stay managed through the website. Mobile users can explore plans, but iOS must not contain Stripe checkout, billing portal, payment setup, or Apple-risky direct purchase flow.

Key requirements:

1. Source of truth
- Make the server/API the single source of truth for Ora plan metadata.
- Website and mobile must both render the same Ora plan data from the server.
- Remove or stop relying on hardcoded website plan cards where they can drift from server/mobile.
- Fix the current Deep Wave price mismatch:
  - Server/mobile currently show Deep Wave as $40/mo.
  - Website hardcodes Deep Wave as $65/mo in billing/pricing pages.
  - Confirm the correct canonical price, then update every surface to match.

2. Ora-only plan features
Plan cards shown inside Ora surfaces must NOT include AI Builder features.

Remove from Ora plan cards:
- Builder credits
- concurrent builds
- build queue
- “Built with MustaFlow” badge
- connectors if they refer to AI Builder integrations
- publishing/build/deployment features
- ORAX/AI Builder-specific capability names

Ora plan cards should only include Ora-related features, for example:
- Ora message limits
- Ora image limits
- Talk to Ora voice minutes
- reset windows
- Instant replies
- Deep Thinking availability
- memory/history capability if applicable
- language/focus/realtime voice features if applicable
- support level if product wants it

If Builder plans still exist elsewhere, keep those separate. Ora plan metadata must be product-scoped, e.g. oraTiers, not mixed with builderTiers.

3. Website surfaces to fix
Review and update:
- website pricing page
- website billing page
- Ora settings page
- any Upgrade / Deep Thinking locked state
- any plan cards used in Ora flows

Website Ora surfaces should render Ora-only tiers from the server/API, not duplicated hardcoded arrays.

4. Mobile surfaces to fix
Review and update:
- Ora Mobile Settings → Plan & billing
- Account Sync diagnostics
- locked Deep Thinking prompts
- any “Explore plans” / plan comparison UI

Mobile should:
- show Free / Core Pack / Deep Wave cards
- show current plan badge
- show status, renewal/cancel date
- show Ora-only features
- show server-provided prices
- show Account Sync rows
- not include Builder features

5. Payments / upgrade behavior
Keep payments managed through the website.

Mobile should NOT wire:
- Stripe checkout
- billing portal
- payment method setup
- in-app Stripe payment flow

Recommended mobile copy:
“Manage your Ora plan on the MustaFlow website. Sign in there with the same account; your plan unlocks automatically here.”

Optional mobile UX:
- Add an “Explore plans” section.
- Allow comparing plans.
- The CTA should be informational, not a hidden Stripe checkout.
- Do not add direct web checkout links until App Store/legal review approves external purchase link eligibility.

6. Account sync behavior
After a user pays on website:
- Mobile must unlock the same tier after sign-in.
- Account Sync must confirm:
  - Local signed in
  - Token present
  - Server recognized
  - Billing tier
  - Chat tier
  - Public session tier
  - Local session tier
- All tier rows should match for a healthy paid account.

7. Tests to add/update
Add tests that prove:
- Ora mobile plan cards render server tier priceUsd/features.
- Ora mobile settings does not import or call checkout/portal/payment setup.
- Website Ora plan cards do not hardcode different prices from server.
- Website Ora plan cards do not contain Builder-only words/features.
- Mobile Ora plan cards do not contain Builder-only words/features.
- Deep Wave price is identical across server, website, and mobile.
- Account Sync still verifies paid tier correctly.
- Locked Deep Thinking prompts direct users to website-managed plan flow, not Stripe checkout.

8. Acceptance criteria
Done only when:
- Free/Core/Wave names match across website + mobile.
- Prices match across website + mobile.
- Ora plan features are Ora-only.
- No AI Builder features appear in Ora plan cards.
- Mobile has no wired Stripe checkout/billing portal/payment setup.
- Website remains the only payment management surface.
- Paid website account unlocks the same tier on mobile.
- All relevant tests and typechecks pass.
