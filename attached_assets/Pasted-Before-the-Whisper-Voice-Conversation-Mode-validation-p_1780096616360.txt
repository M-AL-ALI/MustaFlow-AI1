Before the Whisper / Voice Conversation Mode validation, please fix this important Ora upload UX issue.

Current issue:
There is no clear visible button for uploading pictures/images in the Ora chat interface, even though Phase 5 image upload and analysis is supposed to support PNG/JPG/WEBP.

We need Ora to support professional file/image upload behavior similar to a modern AI chat experience.

Required fix:

1. Clear upload button for pictures and files

The Ora composer should have a clear upload/attachment button that supports:

* images: PNG, JPG, JPEG, WEBP
* documents: PDF, DOCX, TXT
* datasets: CSV, XLSX

The visitor should easily understand they can upload pictures and files.

Recommended UI:

* keep the paperclip attachment button
* add tooltip or label: “Upload image or file”
* accepted file types should include all supported Ora types
* show a preview chip after upload
* image uploads should show thumbnail preview
* document/dataset uploads should show file chip and metadata

2. Drag-and-drop upload

Add drag-and-drop support to Ora Panel and Ora Bubble.

Expected behavior:

* visitor drags a file or picture into the Ora chat area
* Ora shows a visual drop zone overlay, such as:
    “Drop image or file to upload”
* when dropped, the file automatically uploads through the existing upload flow
* upload state is shown
* successful upload creates the correct chip:
    * image thumbnail chip for PNG/JPG/WEBP
    * file chip for PDF/DOCX/TXT
    * dataset chip for CSV/XLSX
* unsupported file type shows safe error
* oversized file shows safe error
* failed upload keeps UI stable

3. Paste upload from clipboard

Add paste support inside the Ora composer/message area.

Expected behavior:

* visitor copies an image from clipboard and pastes into Ora
* if clipboard contains an image, Ora automatically uploads it
* if clipboard contains a supported file, Ora uploads it
* if clipboard contains normal text, it should paste into the text box normally
* image paste should create an image thumbnail chip
* file paste should create a file chip if browser supports pasted files
* unsupported pasted file shows safe error

Important:
Do not break normal text paste. Text paste must still work normally.

4. Upload behavior should reuse existing routes

Use the existing upload system:

* POST /api/public-ai/upload

Do not create new upload routes unless absolutely required.

The upload route should continue detecting:

* image branch
* document branch
* dataset branch

5. One attachment at a time unless already supported

If the current Ora composer supports only one attachment at a time, keep it that way for now.

If user drops or pastes a new file while another attachment is already active:

* either replace the current attachment after confirmation
* or show: “Remove the current attachment before uploading another.”

Do not silently overwrite an attachment without clear behavior.

6. Mobile support

For mobile:

* upload button should open the native file/photo picker
* image selection from camera roll should work if browser supports it
* drag-and-drop may not be available on mobile, but paste/upload button should still work
* UI should stay clean and not crowd the voice/mic/send buttons

7. Accessibility

Upload controls must include:

* aria-label: “Upload image or file”
* tooltip
* visible focus state
* keyboard access
* clear error messages

Drop zone must announce state safely for accessibility if practical.

8. Privacy and safety

Do not log:

* file contents
* image bytes
* base64
* pasted content
* raw filenames if they could be private
* user message text

Do not store files/images permanently.

Do not send uploads to Builder/project memory.

Keep all existing Phase 2/3/5 temporary storage and session-scoped protections.

9. Limits must still apply

Drag/drop/paste must respect the same existing limits:

* file type validation
* magic-byte validation
* image size limit
* document size limit
* dataset size limits
* image count limit
* file count limit
* session scoping
* cross-session protection

10. Required validation

Please provide proof for:

* visible upload button exists in Ora Panel
* visible upload button exists in Ora Bubble
* image upload button accepts PNG/JPG/WEBP
* document upload still accepts PDF/DOCX/TXT
* dataset upload still accepts CSV/XLSX
* drag-and-drop image upload works
* drag-and-drop file upload works
* paste image upload works
* normal text paste still works
* unsupported dropped file shows safe error
* oversized dropped file shows safe error
* image thumbnail appears after upload
* document/dataset chip appears after upload
* mobile file picker still works
* no new backend route added
* no permanent storage added
* no file/image content logged
* Phase 1 chat still works
* Phase 2 document analysis still works
* Phase 3 dataset analysis still works
* Phase 5 image analysis still works

* typecheck/lint/format pass
* rollback plan is clear
