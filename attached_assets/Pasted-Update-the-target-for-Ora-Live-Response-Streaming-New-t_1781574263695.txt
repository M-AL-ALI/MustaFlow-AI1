Update the target for Ora Live Response Streaming.

New target:
Aim for 97% ChatGPT/DeepSeek-style streaming user experience.

Important:
This does not mean copying ChatGPT or DeepSeek branding or internal systems. It means Ora should feel almost as smooth, fast, polished, and reliable from the user’s perspective.

97% UX acceptance standard:

1. Instant response state

* User message appears immediately.
* Ora bubble appears immediately.
* Thinking state appears instantly.
* No empty dead time after sending.

2. Real token streaming

* Do not fake streaming with CSS only.
* Stream real provider tokens through backend SSE.
* Text should appear progressively while the model is generating.

3. Smooth visual rendering

* Token/word fade-in should feel premium.
* Add a subtle blinking cursor while streaming.
* Avoid jitter, layout shift, duplicate spacing, or broken markdown.
* Markdown should render cleanly while streaming, including bullets, code blocks, and tables.

4. Speed target

* First visible Ora state: under 100 ms.
* First streamed token: as fast as provider allows.
* If provider takes more than 2 seconds, show calm thinking animation.
* Long answers must start streaming before the full answer is complete.

5. Scroll behavior

* Auto-scroll only when the user is near the bottom.
* If the user scrolls up, do not force-scroll.
* Show “Jump to latest” button.
* Mobile must not jump when keyboard opens/closes.

6. Reliability

* No stuck “thinking.”
* No duplicate assistant messages.
* No lost response after refresh if already saved.
* No repeated final chunks.
* No token order issues.
* No broken UTF-8 characters.
* Done/error state must always close the stream cleanly.

7. Error handling

* If streaming fails before first token, fallback to another provider or non-streaming endpoint.
* If streaming fails after partial tokens, keep the partial response.
* Show retry button.
* Retry should continue cleanly without duplicating the user message.

8. Markdown/code quality

* Streaming markdown must not visually break.
* Code blocks should remain readable while streaming.
* Copy button should appear after completion.
* Tables/lists should render correctly after completion.
* Do not show raw SSE artifacts to the user.

9. Accessibility

* Respect prefers-reduced-motion.
* Use aria-live=“polite”.
* Keep text readable in dark/light mode.
* Animation should be subtle, not distracting.

10. Ora isolation

* No AI Builder words.
* No Builder handoff.
* No Builder CTA.
* No Builder token.
* No Builder route.
* No Builder statuses.
* Existing Ora isolation quality-gate test must continue passing.

11. Tests required
    Add automated tests for:

* start event
* status event
* token event
* done event
* error event
* token order
* no duplicate assistant bubble
* no stuck thinking state
* partial response preserved after stream error
* retry after stream error
* markdown streaming
* code block streaming
* reduced-motion fallback
* auto-scroll / jump-to-latest
* no Builder words in streaming statuses/UI

12. Live benchmark required
    Add a streaming category to the Ora benchmark and score it separately.

Streaming benchmark target:
Minimum 90% to accept.
Stretch target 97%.

Final acceptance:
Ora Live Response Streaming should feel 97% close to ChatGPT/DeepSeek from the user’s perspective: fast, smooth, reliable, premium, mobile-safe, and fully Ora-isolated.
