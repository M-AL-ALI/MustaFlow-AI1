2. Main product direction

Ora Mobile should be the same Ora model and same Ora assistant experience as the website, but packaged as a mobile app for:

* iOS
* Android

Ora Mobile is not Builder Mode.
Ora Mobile is not Agentic Builder.
Ora Mobile is completely separate from MustaFlow AI Builder.

It should use the same public Ora backend/model that powers the website Ora experience.

The goal is:

“Ora by MustaFlow” as a mobile AI assistant app for users, using the same Ora intelligence already available on www.mustaflow.com, but redesigned for mobile.

3. Ora Mobile required features

Ora Mobile should include:

Core chat

* Clean mobile chat interface
* Welcome screen for Ora by MustaFlow
* Message history inside the session
* Streaming AI responses if the web version supports it
* Typing/thinking state
* Retry failed message
* Stop generation if supported
* Copy response
* New chat/session reset

Same Ora model/backend

* Reuse the same website Ora API routes where possible
* Do not create a separate AI brain unless absolutely required
* Mobile should call the same public Ora backend
* Keep model routing consistent with the website
* Keep safety, rate limits, and cost controls consistent with website Ora

File and image support

Match the website Ora capabilities as much as possible:

* Upload PDF
* Upload DOCX
* Upload TXT
* Upload CSV/XLSX if already supported on web
* Upload image/photo
* Camera capture
* Gallery upload
* File analysis result inside chat

Voice support

Ora mobile should support:

* Voice input / speech-to-text
* Microphone permission flow
* Optional text-to-speech reply playback if website Ora supports it
* Clean voice UI state: listening, processing, speaking

Web/search support

If website Ora has search enabled:

* Mobile should expose it through the same backend
* User should not need to understand search mode
* Ora decides when search is needed, or UI can show a simple search-enabled state

Mobile UI quality

The app should feel like a premium AI assistant:

* Modern mobile-first layout
* Bottom input bar
* Attachment button
* Microphone button
* Send button
* Ora dynamic icon/avatar
* Thinking animation
* Smooth scrolling
* Safe-area support for iPhone notch and Android navigation
* Light/dark mode support if possible
* Good empty state examples
* Error states that explain what happened

Session and privacy

* Ora mobile should follow the same privacy/session rules as web Ora
* No connection to user Builder projects
* No project files access
* No internal MustaFlow workspace access
* Temporary uploads should follow the same TTL/cleanup rules as the web
* Anonymous/public usage is okay if that is how web Ora works
* If login is needed later, keep it optional and do not block the first version unless required
