Separate task — Phase 9A: MustaFlow AI Image Generation & Image Editing Studio

Please create a separate implementation plan for a new Image Generation and Image Editing feature inside MustaFlow AI.

This must be separate from:

* Phase 8B Knowledge Vault work
* RAG
* AI memory
* Knowledge-aware reporting
* Web Search
* Advanced Charts
* Builder/Developer/Plan mode changes unless explicitly needed for integration

Do not mix this task with the Knowledge Vault roadmap.

Goal:

Build a professional AI image studio that lets users generate new images from text prompts and also modify/edit uploaded images.

This should support many image use cases, not only simple pictures.

Core features required:

1. Text-to-image generation

Users should be able to type a prompt and generate images.

Examples:

* logos
* app icons
* website hero images
* product mockups
* marketing banners
* social media graphics
* report cover images
* splash screens
* app store graphics
* UI illustrations
* business graphics
* realistic photos
* cartoon images
* 3D-style visuals
* futuristic graphics
* dynamic atom icons
* AI assistant icons
* brand mascots
* background images
* thumbnails
* posters
* flyers
* ads
* presentation visuals

2. Image editing / uploaded image modification

Users should be able to upload an image and ask MustaFlow AI to modify it.

Supported editing examples:

* remove background
* replace background
* add objects
* remove objects
* change colors
* change style
* improve lighting
* make image sharper
* upscale / enhance quality if supported
* convert to cartoon
* convert to realistic style
* convert to icon style
* create transparent background
* create app icon from uploaded logo
* create logo variations
* create banner from uploaded image
* create social post from uploaded image
* crop / resize / reframe
* generate variations from uploaded image

3. Dynamic image generation options

Add dynamic options so users can control the result.

Suggested controls:

* style: realistic, 3D, cartoon, minimal, futuristic, professional, luxury, playful, tech, industrial, food, mechanic, medical, business
* purpose: logo, app icon, banner, hero image, social post, report cover, presentation image, product image
* size/aspect ratio: square, portrait, landscape, wide banner, app icon, story/reel, presentation
* background: transparent, solid color, gradient, realistic, abstract
* quality: draft, standard, high
* number of variations
* brand colors
* text/no text
* safe-for-business mode
* regenerate variation
* create similar
* edit selected result

4. MustaFlow brand integration

The image studio should connect with app/project branding.

When a user is building an app, the image tool should be able to generate:

* app logo
* app icon
* favicon
* splash screen
* onboarding illustrations
* empty-state illustrations
* website hero image
* store listing graphics
* promotional banners
* report cover art

The system should be able to use project information such as:

* app name
* industry
* target users
* brand colors
* selected theme
* logo preference
* platform: web / iOS / Android

5. User workflow

Suggested UI flow:

A. Generate New Image

* user enters prompt
* user chooses purpose/style/size
* user clicks Generate
* system shows generated image results
* user can save, download, regenerate, create variation, or use in project

B. Edit Uploaded Image

* user uploads image
* preview appears
* user enters edit instruction
* user chooses output size/style/background
* system generates edited result
* user can compare before/after
* user can save, download, regenerate, or use in project

C. Project Asset Flow

* user selects “Use in Project”
* user chooses destination:
    * app logo
    * app icon
    * splash screen
    * page image
    * banner
    * report cover
    * media library
* asset is saved to the project library

6. Storage and asset management

Add an image asset library.

Each generated/edited image should save metadata:

* id
* userId
* projectId if applicable
* prompt
* edit instruction if applicable
* source image reference if applicable
* image type/purpose
* style
* size/aspect ratio
* provider/model used
* createdAt
* updatedAt
* file URL/storage path
* thumbnail URL
* status
* safety status

Do not store raw API secrets.

Do not expose provider keys to the frontend.

7. API routes

Create authenticated backend routes only.

Suggested routes:

* POST /api/images/generate
* POST /api/images/edit
* POST /api/images/variations
* GET /api/images
* GET /api/images/:id
* DELETE /api/images/:id
* POST /api/images/:id/use-in-project

All routes must:

* require authentication
* enforce ownership
* validate file type and size
* not expose provider API keys
* not expose another user’s assets
* support project ownership checks when projectId is used

8. Upload requirements

For image editing, support uploads:

* PNG
* JPG / JPEG
* WEBP

Optional later:

* SVG
* HEIC conversion
* PDF page-to-image extraction

Add limits:

* max image size
* max file size
* allowed MIME types
* safe filename handling
* virus/magic-byte validation if existing upload utility supports it

9. Safety and policy controls

The image feature must include safety rules.

Do not generate or edit:

* explicit sexual content
* illegal content
* hateful/extremist content
* instructions for harm
* copyrighted logo copying that violates brand rules
* impersonation/deceptive identity content
* private sensitive images without user approval
* unsafe medical/legal deception

For brands/logos:

* allow original brand-inspired designs
* do not copy protected logos exactly
* do not generate fake official logos for companies like Apple, Google, Microsoft, OpenAI, etc.
* if user asks for a logo, create an original design

10. Cost controls

Image generation can cost more than embeddings, so add controls.

Required:

* per-user daily generation limit
* per-project generation count
* rate limit
* prevent repeated accidental generation
* show loading/cost warning if needed
* require confirmation before generating many images
* store generation status
* handle provider errors safely

Suggested limits:

* draft mode: lower cost
* high-quality mode: limited
* max 4 images per request
* max upload size limit
* admin-configurable monthly limit

11. Provider design

Build provider abstraction so the system is not locked to one model.

Suggested interface:

generateImage({
  prompt,
  size,
  style,
  quality,
  count,
  transparentBackground,
  userId,
  projectId
})
editImage({
  sourceImage,
  instruction,
  mask?,
  size,
  style,
  quality,
  transparentBackground,
  userId,
  projectId
})

Provider keys must stay server-side.

The frontend should never receive the provider API key.

12. Frontend UI requirements

Add an Image Studio UI.

Suggested sections:

* Generate tab
* Edit tab
* My Images / Asset Library tab

Generate tab:

* prompt box
* style selector
* purpose selector
* aspect ratio selector
* quality selector
* transparent background toggle
* number of variations
* generate button
* result grid

Edit tab:

* upload/drop image area
* image preview
* edit instruction box
* style/size controls
* before/after comparison
* generate edited image button

Asset Library:

* generated images
* edited images
* thumbnails
* search/filter by project/purpose/style/date
* download
* delete
* use in project

13. Project integration

If user is inside a project, generated images should optionally attach to that project.

Examples:

* Set as app icon
* Set as logo
* Add to media library
* Insert into landing page
* Use as report cover
* Use as presentation graphic
* Use as splash screen

Do not automatically change project files without user confirmation.

14. Privacy requirements

* Uploaded images belong only to the authenticated user.
* User can delete generated images.
* User can delete uploaded source images.
* Do not use uploaded/generated images for training unless explicitly allowed by provider terms and user consent.
* Do not log image content or base64.
* Do not log prompts containing sensitive information if avoidable.
* Store only safe metadata.
