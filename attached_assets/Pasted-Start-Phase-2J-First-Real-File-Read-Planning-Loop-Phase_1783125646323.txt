Goal

Phase 2J should make Orax take the next Codex-like step: after inspecting the project, it should safely read relevant project files and produce an inline plan based on actual file contents.

This phase should not edit files yet. It should only:
1. choose likely relevant files,
2. read safe file contents,
3. return a concise plan grounded in those files,
4. show everything inline in the project thread.

In simple words:

User asks: “Fix the login error.”
Orax Desktop verifies project context.
Orax inspects project structure.
Orax selects likely auth/login files.
Orax reads only safe, allowed files.
Orax replies inline: “I inspected these files. Here is the plan.”

Do not touch Ora, public-ai chat, AI Builder, credits, or normal project chat.

High-Level Flow

1. User sends a message in an Orax Project thread.
2. Backend resolves project/source/host context.
3. Backend queues `run_project_thread`.
4. Desktop verifies `.orax/project.json`.
5. Desktop runs `inspectLocalProject()`.
6. Desktop selects relevant files from the project using the user message + inspection result.
7. Desktop reads safe files.
8. Desktop returns:
   - projectInspection
   - selectedFiles
   - fileReadSummary
   - suggestedPlan
9. Backend writes a human-readable assistant message inline into the thread.
10. Website/mobile show that message as normal thread content.

Safety Rules

File selection and reading must be strict.

Never read:
- .env / .env.*
- *.pem
- *.key
- *.p8
- *.p12
- *.pfx
- id_rsa*
- secrets.*
- credentials.*
- token.*
- node_modules/**
- .git/**
- dist/**
- build/**
- out/**
- coverage/**
- .next/**
- .expo/**
- .turbo/**
- .cache/**
- binary/image/video/archive files
- files outside sourceLocalPath

Limits:
- max selected files: 8
- max file size: 200KB
- max content preview per file: 24KB
- max total content preview: 80KB
- max traversal depth: 5
- max candidate files scanned: 500

Allowed file extensions:
- .ts
- .tsx
- .js
- .jsx
- .json
- .md
- .css
- .scss
- .html
- .yml
- .yaml
- .toml
- .config.js
- .config.ts
- .mjs
- .cjs

Path safety:
- Normalize all relative paths.
- Reject absolute paths.
- Reject paths containing `..`.
- Resolve final path and verify it starts with sourceLocalPath.
- Do not follow symlinks outside sourceLocalPath.
