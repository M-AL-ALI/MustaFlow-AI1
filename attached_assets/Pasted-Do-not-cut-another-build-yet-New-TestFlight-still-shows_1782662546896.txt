1. Remaining account-sync bug: auth readiness race

Latest main includes /api/public-ai/session inside pathRequiresAuth(), but that is not enough.

In artifacts/ora-mobile/lib/auth-client.ts, requireAuthToken() currently allows anonymous when _authIsSignedIn is false.

Problem:
On startup, _authIsSignedIn starts false and _authIsLoaded starts false.
setAuthState(isLoaded, isSignedIn) is called from a React effect in app/(home)/_layout.tsx.
A child screen effect can call getOraSession() before that module-level auth state updates.
Then requireAuthToken() sees _authIsSignedIn=false and returns null.
So /api/public-ai/session can still be created anonymously/free even though the user is actually signed in.

Required fix:
For paths in pathRequiresAuth(), do not allow anonymous while auth is not loaded.
requireAuthToken() should behave like:
- if auth is not loaded: wait/retry briefly, then throw TokenUnavailableError
- if auth is loaded and isSignedIn=false: allow anonymous
- if auth is loaded and isSignedIn=true but no token: retry, then throw
- if token exists: send Bearer

This must prevent signed-in startup from ever creating an anonymous Ora session.

2. getOraSession() must wait for auth readiness

In artifacts/ora-mobile/app/(home)/index.tsx, getOraSession() runs in an effect based on isSignedIn.

Required fix:
- Pull isLoaded from useAuth(), not only isSignedIn.
- Do not call getOraSession() until isLoaded=true.
- If signed in and TokenUnavailableError occurs, do not set a Free/anonymous session. Show “Re-sync sign-in” or retry.
- Add a retry after auth becomes ready.
- On sign-in, force-refresh the Ora session after a valid token is available.
- On sign-out, explicitly reset/recreate anonymous session.

3. Account Sync can give false confidence

Current /api/ora/account-consistency is useful, but it does not prove the actual current /api/public-ai/session cookie is authenticated.

It reports billing tier and chatSession tier from the same server-side resolver, so those can match while the mobile app’s actual public Ora session was created anonymously earlier.

Required fix:
Account Sync must include an actual public Ora session probe using the same mobile path:
- call /api/public-ai/session with required auth
- confirm returned tier/isPaid matches billing tier
- confirm the app’s local Ora session tier matches that response
- display:
  - localSignedIn
  - tokenPresent
  - serverRecognizedUser
  - billingTier
  - publicOraSessionTier
  - localOraSessionTier
  - sessionAuthenticated yes/no

If billing is Core but publicOraSessionTier or localOraSessionTier is Free, Account Sync must fail.
