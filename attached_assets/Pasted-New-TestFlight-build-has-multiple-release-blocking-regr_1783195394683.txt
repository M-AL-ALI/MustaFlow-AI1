Blocker 1 — Ora mobile account/session is not synced with website billing
Screenshot from mobile Settings diagnostics shows:
- Clerk token: present
- Billing tier: Core Pack (active)
- Chat tier: Free
- Build: Version 1.0.0 (39)
- Plan mismatch: billing says Core Pack but chat session says Free
- POST /api/public-ai/session returns 429: “You have started too many Ora sessions today”
- POST /api/public-ai/chat returns 401: “No active session. Please start a session first.”
- POST /api/public-ai/chat/stream returns 401: “No active session. Please start a session first.”

This is the same core failure as before: billing/auth resolves paid user correctly, but the public Ora chat session resolves as Free or cannot be created. The 429 session limit is especially wrong for a signed-in paid Core Pack user. A signed-in paid user must not be blocked by anonymous/free session limits, and mobile should not repeatedly create new public sessions during diagnostics or startup.

Please verify and fix:
1. /api/public-ai/session must receive the Clerk bearer token from mobile every time a signed-in user calls it.
2. requireAuthToken / pathRequiresAuth must include /api/public-ai/session and must not silently call it anonymous when signed in.
3. The server session resolver must use the authenticated user/tier for signed-in users and must not count them as anonymous/free.
4. The session endpoint must be idempotent for an existing signed-in user/session. Diagnostics and app startup should reuse/refresh the same session instead of creating many new sessions and hitting 429.
5. If a signed-in paid user hits any session cap, the error must clearly show the authenticated userId/tier in server logs so we can prove whether it resolved as paid or anonymous.
6. Fix Settings diagnostics so “Test Ora chat” does not create extra sessions repeatedly or exhaust the quota. It should either reuse the current session or call a non-mutating diagnostic endpoint.
7. Acceptance: on the same account, website and mobile must show the same tier. Billing tier = Chat tier = Public session tier = Local session tier = Core Pack. Then POST /chat and /chat/stream must return 200, not 401.
