Billing, Usage, and Account Identity

Orax Desktop must require users to sign in with the same MustaFlow AI account used on the website.

Reason:
Orax usage, credits, billing, plan limits, support, and audit logs must be tied to the correct MustaFlow user account.

Account identity:
- Every Orax Desktop session must be linked to a MustaFlow userId.
- The same userId must be used across:
  - MustaFlow website
  - Orax Desktop
  - Orax Web
  - Orax Mobile
- Usage and billing should be tracked by userId and workspace/accountId, not by device alone.

Device identity:
- Each installed Orax Desktop app should also register a deviceId/hostId.
- The deviceId identifies which computer performed the work.
- The userId identifies who owns the work and who should be billed.

Billing model:
- Orax actions should report usage events to MustaFlow Cloud.
- Usage events should include:
  - userId
  - workspaceId/accountId if applicable
  - hostId/deviceId
  - projectId
  - threadId
  - action type
  - model used
  - tokens/compute units if applicable
  - timestamp
  - success/failure status

Examples of billable/trackable Orax usage:
- model requests
- repository analysis
- image/screenshot analysis
- file analysis
- long-running agent task execution
- cloud relay usage if applicable
- premium integrations if applicable

Non-billable or low-cost local events can still be logged for audit:
- local file read metadata
- local command started/completed
- approval accepted/denied
- Git status checked

Credits:
- Orax should check the user’s plan/credits before starting a billable model task.
- If credits are insufficient, Orax should show an inline message:
  “You need more credits to continue this Orax task.”
- The message should link to Billing & Usage on the MustaFlow website.
- Do not mix Orax usage with Ora chat history, but billing/account balance can be shared at the account level.

Desktop app UI:
The Orax Desktop sidebar/profile menu should show:
- signed-in user name/email
- current plan
- credit/usage summary
- Billing & Usage link
- Manage Account
- Help & Support
- Sign out

Security:
- Do not display or store the user password.
- Store session tokens securely using the OS credential store.
- All usage reporting must avoid leaking secrets, raw terminal secrets, private env vars, or sensitive file contents unless explicitly needed and approved.
