Thank you for finding this. This is a critical blocker.

Decision: Proceed with Option A.

We should use a direct OpenAI API key for embeddings instead of the Replit AI integrations proxy, because the Replit proxy does not support POST /embeddings.

Phase 8B-1 and Phase 8B-2 should stay open until this is fixed and live validation passes.

Required fix:

1. Add direct OpenAI embedding support

Use a server-side secret:

OPENAI_API_KEY

Do not expose this key to the frontend.

Do not store it in public code.

Do not use the Replit AI proxy for embeddings.

The embedding call should go directly to the OpenAI embeddings API using:

* model: text-embedding-3-small
* dimension: 1536
* endpoint: OpenAI embeddings endpoint
* server-side only

2. Update generateEmbedding()

Fix artifacts/api-server/src/lib/embeddings.ts.

Current problem:

* generateEmbedding() catches the proxy failure
* returns null
* the vault embedding service treats that as a soft skip
* reindex reports success
* but no vectors are stored

New required behavior:

* If OPENAI_API_KEY is missing, return a clear provider-not-configured error
* If the embedding API returns 400/401/429/500, return a real error
* Do not silently return null
* Do not mark entries as indexed if no vector was generated
* Do not insert rows with embedding = NULL and claim success
* Log only safe metadata, not chunk text

3. Update vault embedding service

Fix vault-embedding-service.ts.

Required behavior:

* If embedding generation fails, the reindex result must report failure
* indexed count must only increment when at least one valid vector is stored or all existing vectors are already valid
* If no vectors were created, do not report the entry as indexed
* vault_embeddings.embedding must be non-null for indexed chunks
* GET /api/vault/:id/embedding-status must accurately show:
    * not_indexed when no embeddings exist
    * indexed when vectors exist and sourceVersion matches entry version
    * out_of_date when vectors exist but sourceVersion is older than entry version

4. Add configuration validation

On API server startup or first embedding attempt, clearly detect:

* OPENAI_API_KEY missing
* invalid OpenAI API key
* embeddings endpoint unavailable
* wrong model/dimension

Return safe error messages such as:

Embedding provider is not configured. Please add OPENAI_API_KEY.

Do not expose the actual key.

5. Add tests / validation

After the fix, run a live validation with Clerk auth again:

* create 4–10 vault entries
* run POST /api/vault/reindex
* confirm response shows indexed count correctly
* query DB:

SELECT COUNT(*) FROM vault_embeddings WHERE embedding IS NOT NULL;

Expected result:

* count must be greater than 0

Then verify:

* semantic search returns results
* similarity score displays
* chunk preview displays
* clicking a result opens the entry viewer
* no raw vectors are returned
* no chunk text is logged
* no query text is logged if avoidable

6. Fix the false success bug

The current behavior where reindex returns:

{ total: 4, indexed: 4, failed: 0 }

while DB has:

embedding IS NOT NULL = 0

is unacceptable.

After the fix, this must never happen.

If embeddings fail, reindex must report failure.
