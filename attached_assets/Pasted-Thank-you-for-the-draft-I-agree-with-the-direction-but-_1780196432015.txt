Thank you for the draft. I agree with the direction, but I want to control the scope carefully.

Decision:

Proceed with Phase 9A-1 only first.

Do not propose or start all five sub-phases together as one giant implementation.

The Image Studio should be split into separate tasks:

* 9A-1 — Architecture + Text-to-Image MVP
* 9A-2 — Uploaded Image Editing
* 9A-3 — Asset Library + Search/Filters
* 9A-4 — Brand Kit + Prompt Assistant + Multi-size export
* 9A-5 — Advanced tools: variations, background removal, upscale, crop/resize, masking scaffold

For now, start with 9A-1 only.

Important adjustment:

9A-1 should create the foundation and a working text-to-image MVP, but it must not include image editing yet.

Image editing/upload modification belongs to 9A-2.

Provider decision:

Use OpenAI as the first provider, but do not hard-code the system to OpenAI only.

Create a provider interface so we can add other image providers later.

Use environment-based configuration:

* IMAGE_PROVIDER=openai
* IMAGE_MODEL=<configured image model>
* OPENAI_API_KEY or a dedicated OPENAI_IMAGE_API_KEY

Provider keys must stay server-side only.

Do not expose image provider keys to the frontend.

Do not commit keys to code.

Do not print keys in logs.

Important lesson from embeddings:

Do not assume the Replit AI proxy supports image generation or editing.

Before building against the Replit proxy, verify it supports the exact image endpoints needed.

If not confirmed, use direct provider API calls server-side, like we did for embeddings.

Storage decision:

Use Cloudflare R2 as the production storage target.

Do not store generated image base64 in the database.

Database should store metadata and file URLs/storage keys only.

For development:

* local dev fallback is acceptable only for development
* if R2 is missing in production, the feature should show a clear configuration error
* do not silently generate images and lose them
* do not use fake placeholder URLs in production

Credits decision:

Make credit pricing configurable, not hard-coded forever.

Initial suggested default:

* draft = 1 credit per image
* standard = 3 credits per image
* high = 6 credits per image

Also enforce:

* max 4 images per request
* daily user generation limit
* monthly/project cap later
* clear confirmation before high-quality or multi-image generation
* refund credits if provider generation fails
* do not refund if user deletes a successfully generated image
