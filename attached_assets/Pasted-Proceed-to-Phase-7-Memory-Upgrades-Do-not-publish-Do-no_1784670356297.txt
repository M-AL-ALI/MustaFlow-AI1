Proceed to Phase 7: Memory Upgrades.

Do not publish. Do not submit TestFlight.

Goal:
Improve Ora memory so it feels closer to ChatGPT: useful, controllable, project-aware, privacy-safe, and consistent across website and mobile.

Requirements:

1. Audit current memory system:
- memory extraction
- memory save
- memory recall
- memory manager UI
- project-scoped memories from Phase 6
- document memory chip
- mobile memory UI
- privacy/sensitive-memory safeguards

2. Memory scope model:
Support:
- global user memory
- project-specific memory
- optional temporary/session-only memory if already compatible

Rules:
- global memory can apply everywhere
- project memory applies only inside that project
- no project memory leakage across projects
- no cross-user leakage
- user must be able to view/edit/delete/disable memory

3. Memory controls:
Website and mobile should support:
- view memories
- edit memory title/content
- delete memory
- disable/enable memory
- project filter
- memory scope label:
  - Global
  - Project: [name]

4. Better memory quality:
Improve extraction so Ora saves useful durable facts only:
- user/company name
- preferred tone
- preferred language
- brand/style preferences
- repeated project details
- business context
- saved instructions
- file/report preferences

Avoid saving:
- random one-off facts
- sensitive data unless explicitly confirmed
- raw document contents
- passwords/API keys/payment data
- accidental file text

5. Memory usage in prompts:
When building Ora context:
- include relevant global memories
- include relevant memories for current project
- do not include memories from other projects
- rank relevant memories
- keep memory context concise
- explain/use memory naturally, not awkwardly

6. Document memory:
Improve “Remember this document?” flow:
- save clean summary, not raw text
- project-scope it if current project is selected
- show success/failure clearly
- retry if memory summarization fails
- avoid storing sensitive document data without confirmation

7. Website UI:
- Memory manager shows global/project memory
- Filter by project
- Edit/delete/disable controls
- Scope badges
- Clear empty/error states

8. Mobile UI:
- Same controls in compact form
- Project filter
- Scope badges
- Edit/delete/disable
- Back to Ora navigation preserved

9. Tests:
- global memory recall works
- project memory recall works only in correct project
- project memory does not leak into another project
- delete memory removes from prompt context
- disabled memory is not used
- edit memory updates prompt context
- document memory saves summary only
- sensitive data is not saved automatically
- website memory UI wiring
- mobile memory UI wiring

10. Update ORA_FEATURE_REGISTRY if needed.

11. Run fast gate.

12. Commit as scoped Phase 7 commit.

13. Push to GitHub.

14. Run fast gate again on clean tree.

15. Report:
- commit SHA
- changed files
- backend impact
- website impact
- mobile impact
- tests added
- fast gate result
- known limitations
