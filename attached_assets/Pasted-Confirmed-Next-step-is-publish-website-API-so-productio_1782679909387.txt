Verification checklist:

1. Website normal chat
- Open DevTools → Network.
- Send short prompt: “hi”.
- Confirm first token/event arrives quickly, expected around 1–2 seconds on a normal connection.
- Confirm words appear progressively, not all at once after the full answer is complete.

2. Mobile normal chat
- Use latest mobile build pointing to the published API.
- Send the same short prompt.
- Confirm first visible text appears quickly.
- Confirm mobile does not buffer until full response.

3. Long response
- Prompt: “Write me a 500-word explanation of…”
- Confirm response streams continuously.
- It should not wait until the entire answer is finished.

4. Arabic prompt
- Send a short Arabic prompt.
- Confirm first visible token is fast.
- Confirm Arabic text streams normally.

5. Memory-enabled prompt
- Send a personal/memory-style message.
- Confirm response streams first.
- Confirm memory saving still happens after response.
- Memory extraction should not block the visible done event.

6. Web-search prompt
- Confirm search path still works.
- Note: web-search may remain non-streaming or streamingFallback; that is separate from normal chat streaming.

7. Logs
- Confirm timingMs appears with sessionMs, authMs, contextMs, headerFlushMs, ttftMs, streamMs, totalMs.
- Confirm no raw prompt text, raw memory text, or private transcript text is logged.
- Confirm streaming.realTime is true for real provider streaming and false only for large buffered fallback chunks.

Expected result:
- Normal Ora text chat should feel much closer to ChatGPT because first visible token should arrive much faster.
- Full answer can still take time, but the blank waiting period should be much shorter.
