Build a full-stack web platform named MustaFlow AI.

Important:
This must be an ORIGINAL platform. Do not copy Replit branding, logo, exact UI, exact wording, icons, code, or protected design. The goal is to build a Replit-like AI app-building workflow under the MustaFlow AI brand, with original UI, original layout style, original colors, and stronger safety/memory features.

Product name:
MustaFlow AI

Main purpose:
MustaFlow AI is an AI app-builder platform for non-technical users. The user describes what they want to build, and the AI plans, designs, builds, wires, tests, previews, saves, improves, and helps publish complete web, iOS, and Android apps.

This platform must be designed to become smarter over time through project memory, Knowledge Vault, approved lessons learned, fix history, diagnostics history, reusable patterns, and user-approved improvements.

Do not build a shallow mockup. Build a strong foundation with real full-stack structure, clean routing, database-ready models, reusable components, safe task workflow logic, and clear placeholders where real external systems will be connected later.

--------------------------------------------------
OVERALL PRODUCT VISION
--------------------------------------------------

MustaFlow AI should work like this:

User opens MustaFlow AI
→ User creates or opens project
→ User describes app idea in AI Builder
→ AI understands the request
→ AI chooses correct tech stack, framework, pages, backend logic, database, and integrations
→ AI creates a plan
→ AI asks whether to build in Main Agent or Background Agent
→ AI builds the app
→ AI wires pages, frontend, backend, database, and integrations
→ AI shows live preview for Web / iOS / Android
→ AI identifies required API keys and tells user where to add them
→ AI runs tests
→ AI saves version and rollback point
→ AI writes final report
→ User can publish to testing, production, website, TestFlight, App Store, or Play Store workflow

The AI must not only generate text. It must turn user instructions into actual project files, app screens, backend routes, database structures, and preview updates.

--------------------------------------------------
VERY IMPORTANT DEVELOPMENT RULES
--------------------------------------------------

Before building:
1. Inspect the current file structure.
2. Identify existing frontend, backend, routes, database, and config.
3. Do not overwrite working code blindly.
4. Do not create duplicate files with conflicting names.
5. Do not hardcode secrets.
6. Do not expose secret keys to frontend.
7. Do not mix testing keys and production keys.
8. Do not claim the build is complete unless it runs.
9. Create a final validation report.

Agent modes:
1. Lite
   - Fast, small edits, low-cost
   - Used for small UI changes, text changes, simple questions

2. Eco
   - Default mode
   - Balanced cost and capability
   - Used for most normal app building

3. Power
   - Complex features, debugging, integrations, app wiring
   - Should be used only when needed

4. Pro
   - Future/advanced mode placeholder
   - Do not overuse

The system should recommend Eco by default and only recommend Power when the task is complex.

PLAN MODE
--------------------------------------------------

Plan Mode must be inside the AI chat.

When Plan Mode is ON:
- The AI must not change files.
- The AI must analyze first.
- The AI must produce a detailed plan.
- The AI must list affected files/modules.
- The AI must list database changes.
- The AI must list integrations required.
- The AI must list keys/accounts needed.
- The AI must list risks.
- The AI must list testing requirements.
- The AI must ask user approval before building.

After the plan, ask:

“Do you want me to build this in the Main Agent now, or run it as a Background Task?”

Options:
- Build in Main Agent
- Run in Background
- Edit Plan
- Cancel

Plan Mode response structure:
- Summary
- Goal
- Recommended tech approach
- Pages/screens needed
- Backend/API needed
- Database tables needed
- Integrations/keys needed
- Files likely affected
- Risks
- Test plan
- Approval question

- Runs planning/build/fix/test in background

- Shows pass/fail result
