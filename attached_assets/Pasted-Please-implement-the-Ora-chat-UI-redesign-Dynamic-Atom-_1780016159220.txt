Please implement the Ora chat UI redesign, Dynamic Atom assistant icon, thinking states, and Builder CTA logic update.

Goal:
Ora should feel like a premium AI assistant inside MustaFlow, not a heavy boxed widget. The current layout is too crowded, the purple border is too strong, the static “O” icon feels generic, and the “Ready to build this with MustaFlow Builder?” card should not appear on every message.

Required changes:

1. Redesign the Ora chat layout

Make the chat interface cleaner, more premium, and easier to read.

Current issues:
- Too much purple border.
- Chat feels boxed-in.
- Input area is crowded.
- Assistant messages feel heavy.
- Builder CTA card repeats too often.

New layout requirements:
- Keep the dark premium MustaFlow theme.
- Reduce border heaviness.
- Use softer spacing and cleaner message layout.
- User messages should remain right-aligned.
- Assistant messages should be left-aligned with Ora’s Dynamic Atom icon.
- Improve readability with better line height and spacing.
- Avoid the “card inside a card” feeling.
- Keep the layout fully mobile-friendly.

2. Redesign the bottom composer

Replace the current crowded input area with one unified modern composer.

Composer should include:
- Attachment icon on the left.
- Input field in the center.
- Send button on the right.
- Helper text below in a subtle smaller style.
- Message count should be subtle and not visually compete with the input.

Placeholder:
“Ask Ora anything…”

Helper text:
“Upload PDF, DOCX, TXT, CSV, XLSX · Talk in any language”

3. Replace the static Ora “O” icon with a Dynamic Atom icon

Remove the current static purple “O” badge.

Create a Dynamic Atom icon system for Ora.

Visual direction:
- Center glowing core.
- 2–3 orbit rings.
- Subtle orbit motion.
- Optional small particles.
- Smooth premium animation.
- Not too busy.
- Dark-mode friendly.

Recommended colors:
- Primary: violet / purple.
- Secondary: indigo / electric blue.
- Accent: soft cyan or soft pink.
- Green only for success.
- Amber/red only for warning or error.

4. Add Dynamic Atom assistant states

Implement these states:

Idle:
- Soft glow.
- Slow orbit movement.
- Calm pulse.

Thinking:
- Orbit rings rotate.
- Core pulses.
- Small particles move.
- Status text: “Thinking…”

Replying:
- Slightly brighter glow.
- Orbit speed increases slightly.
- Status text: “Replying…”

Uploading:
- Atom with upload/attachment badge.
- Status text: “Uploading…”

Reading document:
- Atom with document badge.
- Status text: “Reading document…”

Analyzing dataset:
- Atom with table/grid badge.
- Status text: “Analyzing dataset…”

Builder-ready:
- Atom with cube/blocks/wireframe badge.
- Only show this when Builder handoff is relevant.

Success:
- Subtle green shimmer or small check accent.

Error/warning:
- Subtle amber/red outline or warning pulse.

5. Add visible assistant status behavior

When the user sends a message, Ora should show a visible working state before and during the reply.

Examples:
- Ora · Thinking…
- Ora · Replying…
- Ora · Reading document…
- Ora · Analyzing dataset…
- Ora · Preparing recommendations…
- Ora · Ready

This should help users know the AI is working and not frozen.

6. Fix Builder CTA logic

Do not show “Ready to build this with MustaFlow Builder?” on every assistant message.

Only show Builder CTA when there is clear build/project intent.

Show Builder CTA for messages like:
- Build this app
- Create this project
- Turn this into an app
- Make this in MustaFlow
- Start project
- Generate builder version
- Continue in Builder
- Open this in Builder
- Create a website/app/tool from this

Do not show Builder CTA for:
- Normal questions
- Memory questions
- General explanations
- Casual chat
- Translations
- Interview help
- Troubleshooting
- Document analysis
- Dataset analysis
- KPI analysis
- Root-cause analysis
- General AI answers

7. Redesign Builder CTA

When Builder CTA is shown, make it smaller and contextual.

Do not use the large repeated card.

Use smaller CTA examples:
- “Open in MustaFlow Builder →”
- “Turn this into a project →”
- “Continue in Builder →”

It should appear only when useful and should not interrupt the chat experience.

8. Update file and dataset UI support

The upload UI and helper text should support:
- PDF
- DOCX
- TXT
- CSV
- XLSX

When a dataset is uploaded:
- Show a dataset chip.
- Use a table/grid icon or Dynamic Atom dataset badge.
- Show row count and column count.
- Show preview if available.
- If sampled/truncated, show a subtle “Sampled” badge.
- If cells were sanitized, show a small info indicator.
- If hidden sheets were skipped, show a small info indicator.

9. Final acceptance criteria

This update is complete only when:
- The static “O” icon is replaced by the Dynamic Atom icon.
- Dynamic Atom has idle, thinking, replying, upload, document, dataset, builder-ready, success, and error states.
- Ora shows visible thinking/task-specific status before and during replies.
- Builder CTA no longer appears on every assistant message.
- Builder CTA appears only for clear build/project intent.
- The bottom composer is redesigned into one clean input bar.
- Helper text and message count are subtle.
- Chat layout has less border heaviness and better spacing.
- Mobile layout remains clean and usable.
- PDF, DOCX, TXT, CSV, and XLSX upload support is reflected in the UI.

Please implement this carefully without breaking existing Ora chat functionality, upload functionality, message limits, language detection, or Builder routing.
