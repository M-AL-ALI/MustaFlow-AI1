New blocker: Account sync is not staying stable all the time.

I tested/observed that mobile can look signed in locally, but Ora sometimes does not stay synced to the website account/plan/history/memories. Please fix this before TestFlight.

Likely root cause:
Mobile API calls attach Clerk auth only if getAuthToken() returns a token at that moment.

Current code:
- artifacts/ora-mobile/app/(home)/_layout.tsx registers setAuthTokenGetter(() => getToken())
- artifacts/ora-mobile/lib/api.ts authHeaders() calls getAuthToken()
- If token is missing/null, jsonRequest still sends the request without Authorization
- Public Ora endpoints like /api/public-ai/chat and /api/public-ai/realtime/session still work anonymously
- So if the app is signed in locally but token retrieval temporarily fails, the server can resolve the request as anonymous/free
- That causes account/plan/memory/history sync to appear intermittent

Required fix:
When mobile believes the user is signed in, Ora requests must NOT silently downgrade to anonymous.

Please implement a mobile auth-stability guard:

1. Track signed-in auth readiness globally
- In artifacts/ora-mobile/app/(home)/_layout.tsx or a small auth-client helper, store:
  - Clerk isLoaded
  - isSignedIn
  - getToken readiness
- Do not let signed-in Ora calls proceed until a Clerk token is available.

2. Add required-auth behavior for signed-in Ora calls
For mobile requests where the UI is signed in and expects user data, require a bearer token:
- /api/public-ai/chat
- /api/public-ai/realtime/session
- /api/public-ai/usage
- /api/me/preferences
- /api/billing/subscription
- /api/ora/conversations
- /api/ora/projects
- /api/ora/assets
- /api/ora/account-consistency
- memory save/load routes

If isSignedIn=true but getToken() returns null:
- Do not send the request anonymously
- Show a clear “Re-sync sign-in” / “Session expired, sign in again” error
- Account Sync should show failure, not anonymous/free
- Talk to Ora should not mint an anonymous realtime session when the user is signed in

3. Add retry/refresh
Before failing, try getToken() again once, preferably with Clerk refresh/no-cache if available.
If token is still null, fail closed.

4. Add diagnostics
Account Sync should explicitly show:
- localSignedIn: yes/no
- tokenPresent: yes/no
- serverRecognizedUser: yes/no
- billing tier
- chat tier
- whether the current Ora session is authenticated or anonymous

5. Add tests
Add/extend mobile source tests to prove:
- signed-in + missing token does NOT call public chat anonymously
- signed-in + missing token does NOT call realtime/session anonymously
- Account Sync warns/fails when signed-in but token missing
- anonymous mode still works only when isSignedIn=false

6. Keep existing behavior for true anonymous users
If isSignedIn=false, anonymous/free Ora is allowed.
If isSignedIn=true, anonymous fallback is NOT allowed.

Acceptance:
- Mobile Account Sync stays stable after app restart, background/foreground, and returning from settings.
- Paid user always resolves paid tier on mobile.
- Talk to Ora mobile never mints as anonymous/free while the user is signed in.
- Website and mobile show the same email, plan, projects, memories, recent conversations, history counts, and support/account diagnostics.
- All existing Talk to Ora parity tests still pass.
- No TestFlight build until this is fixed and verified.
