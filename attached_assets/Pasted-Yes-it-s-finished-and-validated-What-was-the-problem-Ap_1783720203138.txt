What was the problem
Apple rejected your Ora iOS app (MustaFlow, build 42) under Guideline 4.8: an app offering third-party login (Google) must also offer Sign in with Apple with equal prominence.

What I did
A narrow, additive fix — no changes to Ora chat, Talk to Ora, billing, search, images, files, history, ORAX, or the website. Google and email/password login are untouched.

Added the dependency: expo-apple-authentication ~8.0.8 (pinned for SDK 54).
Expo config (app.json): enabled ios.usesAppleSignIn and added the expo-apple-authentication plugin.
New AppleSignInButton.tsx: renders Apple's real native button (theme-aware black/white, full-width, 48px) and runs the true native Apple flow via Clerk's useSignInWithApple() from @clerk/expo/apple — the native Apple sheet / Face ID, then Clerk session creation, with automatic sign-up for brand-new Apple IDs. User cancellation is handled silently.
Wired it in above "Continue with Google" on both the sign-in and sign-up screens.
One important correction along the way
My first attempt used Clerk's startSSOFlow with oauth_apple, but code review caught that this opens a web browser login — the exact pattern Apple rejects. I switched to the genuine native hook (verified against the installed package's source). Second code review passed.

Verified: typecheck, prettier, eslint, and validation (codegen + lint) all pass; architect review PASS. (A @clerk/expo "unable to resolve" line in the web preview is a known Clerk-web-only quirk and doesn't affect iOS builds.)
