I need MustaFlow preview to test the actual generated application, not only static files or a browser WebContainer.

Current problem:
- The Preview tab often renders `/api/projects/:id/preview/*` or a browser WebContainer.
- Container status may appear in the UI, but the iframe does not reliably load the actual running project container.
- This means I cannot properly test backend routes, environment variables, database behavior, server-side rendering, or full app runtime before publishing.

Implement a two-mode preview system:

1. Quick Preview
- Keep the existing static/WebContainer preview for fast frontend editing.
- Label it clearly as "Quick Preview".
- It is for UI and client-side testing only.

2. Full App Preview
- Add a "Full App Preview" mode/button in the Preview tab.
- When started, launch or wake an isolated development container for the current project draft.
- Mount/sync the current draft files into that container.
- Run the project using its real development command.
- Display the actual running container URL inside the Preview iframe.
- Proxy it through an authenticated backend route if needed, rather than exposing an unsafe raw URL.
- Show container startup, building, running, failed, stopped and restarting states.
- Show real runtime logs and server errors in the Preview console.
- Add Restart and Stop controls.

Full App Preview must support:
- frontend routes
- backend/API routes
- server runtime behavior
- project environment variables using preview-safe values
- database connectivity using an isolated preview database or explicitly safe development database
- generated app authentication flows where possible
- file changes refreshing or rebuilding the running container

Security requirements:
- Full App Preview must always require project ownership/authentication.
- Never make current draft files public just because a project was previously published.
- Do not use production secrets or production customer data in preview by default.
- Public published URLs must continue to serve only the published snapshot or production deployment.
- Remove studio-only console bridge behavior from public published apps.
- Preview containers should automatically sleep/stop after inactivity.

- When a production container is unavailable, published sites must correctly fall back to the frozen published snapshot.

Acceptance tests:
1. Editing an unpublished or published project draft is visible in Full App Preview only to its owner.
2. Full App Preview runs the project's real backend route successfully.
3. Full App Preview can display runtime/server errors from the running app.
4. Published public output does not change until the user publishes again.
5. A failed production container still serves the last published snapshot.
6. Public published HTML does not include editor console-bridge behavior.
7. The Preview UI clearly shows whether the user is viewing Quick Preview or Full App Preview.
